# gogh-xr

A Meta Quest 3 WebXR experience built with three.js, Vite and bun. Requirements live in [PRD.md](PRD.md) and the phase plans in [plans/](plans/).

## Make targets

`install build test lint fmt typecheck checkall checkall-ci bundle-check asset-check audio audio-audition bake e2e update-ab dev dev-start dev-stop dev-restart preview pre-commit`

## Ports

- 4252: Vite dev server (`make dev`)
- 4253: Vite preview for the e2e suite (`make preview`, which Playwright's `webServer` also runs)

Both ports live in `scripts/ports.ts`, which `vite.config.ts`, `scripts/dev-stop.ts` and the e2e config read. `E2E_PORT` overrides the preview port.

## Gate rules

- `make checkall` is the fast gate while iterating (lint, typecheck, test, build, bundle-check).
- `make bundle-check` also enforces a gzip size budget on the production JS (`scripts/bundle-budget.ts`, gzip from `node:zlib` at the default level, measured 2026-11-09 on debc2bd). Each budget is the measured size plus a margin of 14.6% to 19% after rounding up to a clean number. Chunks are keyed by name with the content hash stripped: index 160,000 bytes (measured 136,527), three.core 56,000 (48,715), troika-config 50,000 (43,634), and 30,000 for every other chunk, new ones included (largest today is tie-key at 25,230). The JS total budget is 375,000 (measured 323,714). A failure prints each chunk over budget with its size and budget. To raise a budget after a deliberate size increase, edit `CHUNK_BUDGETS`, `DEFAULT_CHUNK_BUDGET_BYTES` or `TOTAL_BUDGET_BYTES` in that file, re-measure with `make build && make bundle-check`, and update the numbers here.
- `make checkall-ci` must pass before any push. It adds gitleaks, `bun audit` and `asset-check`.
- `make checkall-ci` and `make asset-check` need ffmpeg on PATH, and ffmpeg 9.0.2 for the full check. On another build only the `master.ts --check` byte-identity rebuild is skipped, with a `SKIP` line. The validator and its self-test still run, after a `WARN` line. With no ffmpeg on PATH the audio leg fails.
- `make e2e` is local-only and never runs in CI.
- `make update-ab` runs the served A-to-B update check (`scripts/update-ab.ts`, see Updates). It is local-only and not part of `checkall`.
- `tests/e2e/portal.spec.ts` holds a frame-time bar, so it runs in the one-worker `timing` project, the `e2e` project's teardown, after every other spec has finished (`playwright.config.ts`). Naming only it on the command line still runs only it.
- `make bake` regenerates the Starry Night bake outputs (palette, flow field, region ids, and `lights.webp`, the full-resolution scan around the moon and stars) from the 3840 px scan and rewrites their PROVENANCE.md rows. It is not part of `checkall`, and `asset-check` verifies the committed outputs.
- Never pipe a gate. Redirect to a file, capture the exit code, then tail the log.
- No push without Paul's approval.

## Deploy

- A push to `main` deploys GitHub Pages (`.github/workflows/pages.yml`) to `https://gogh-xr.pardev.net`.
- Every push that deploys, docs-only pushes included, is a new build id: the commit SHA is built into a chunk, so `version.json` changes. Open desktop tabs reload by themselves within about 30 s, and XR sessions show the update notice with its Reload (see Updates).
- A Pages deployment is keyed by the commit SHA. Once a deploy for a SHA is cancelled or times out, every later attempt for that same SHA ends at once with "Deployment cancelled". This includes "re-run failed jobs", which also trips on the duplicate `github-pages` artifact, and `workflow_dispatch`. Push a new commit to deploy again.

## URL flags

Parsed in `src/diag/flags.ts`.

- Rule: any new A/B flag registers a group in `src/diag/ab.ts` (`AB_GROUPS`, `createAbGroup`, and the flag's implication in `resolveAb`), so the A/B button can cycle it live in the headset.

- `?diag`: installs `window.__goghDiag()` (renderer info, XR state, frame rates, camera pose, counts). `camera` is the world pose of the camera that rendered the last frame: three's XR camera while presenting, whose matrices include the rig, and the desktop camera otherwise.
- `?iwer`: installs the IWER Meta Quest 3 emulator. Only honoured in `--mode e2e` builds, never in production.
- `?bench=N`: runs the stroke benchmark with N strokes (default 100000, capped at 2,000,000). A non-numeric value uses the default. Strokes fill a full sphere, so every view direction reads the same. In XR, the right controller's A button steps fixed foveation through 0 (the app default), 0.5 and 1. The governor never runs in the bench, so the bench's own foveation steps are the only ones there. Each settings combination, foveation included, records fps, mean, p95 and p99 once its window settles. Results persist in localStorage under `gogh-xr.bench.results.v1`, show on the HUD, and appear as `benchResults` in `__goghDiag()`. Locomotion never runs in the bench, so on the desktop it is mouse look only, from the origin, with no WASD. On the desktop, `[` and `]` step N down and up by 25,000, as the left stick does in XR.
- `&mode=a2c|blend`: benchmark transparency mode, alpha-to-coverage (default) or blended. In the headset, the left controller's X button toggles the mode and resets the order to that mode's default.
- `&size=px`: benchmark stroke size in pixels (default 24).
- `&order=sorted|random`: benchmark draw order. Default is random for a2c and sorted for blend.
- `?hz=72|90|120`: requested XR target frame rate. Without it the quality setting decides: 72 Hz for the default `adaptive-72` and for `beauty-72`, 90 Hz for `adaptive-90`. `?hz=72` selects `adaptive-72`, and `?hz=90` and `?hz=120` select `adaptive-90` and request their rate (see Settings). The bench ignores the quality and defaults to 90. Quest 3 reports `supportedFrameRates` of 72, 80, 90 and 120. In the bench (`?bench`), the left controller's Y button steps the target through the supported rates. No other scene reads left Y.
- `?beauty`: boolean, max-beauty mode. Targets 72 Hz with the max-beauty budget (500k drawn), and the governor starts from the max-beauty densities (`BEAUTY_BAND_DENSITY`). It wins over `?hz`, which it ignores. The bench (`?bench`) ignores it.
- `?slow=<ms>`: testing only. Busy-waits on the CPU for that many ms every frame, to force overruns for the governor. Clamped to 0-50. A malformed value means 0 (off). It is honoured in production builds on purpose: it is URL-only, it only slows the page that asks for it, and the P1.8 headset check needs it on the deployed build.
- `?zdiag=<mode>`: testing only, honoured in production like `?slow`. One stroke depth, order or filtering diagnostic (`src/render/zdiag.ts`), each applied on top of the stroke batch default. Since 2026-11-07 that default is the policy `nowrite` introduced, Paul's headset A/B winner (`BATCH_DEPTH_WRITE` and `DEFAULT_ORDER_POLICY` in `src/render/strokes/batch.ts`, docs/verification.md, nowrite default): batch strokes write no depth and still test against the base meshes, and the chunks draw after the base meshes (render order 2e6 on), in draw-class blocks (`dome`, then `lights` (moon and stars), then `cypress`, then `world`, then `overlay` (lit windows)), back to front within each block. A grid cell holding several classes is one chunk per class. In the Starry Night world (`cypressChunk`) the cypress is one `cypress` chunk whatever cells it spans, drawn before the world so the ground strokes test against its depth. The world also merges (`mergeParts`, `createWorldPartGroup` in `src/paintings/starry-night/world.ts`): its 24 m dome cells by 36° sky sector seen from the painter's eye, and the moon and stars into one `lights` chunk instead of 21. A dome cell that flight (55 m out, up to 40 m above the ground) can bring within 25.5 m stays a chunk of its own, so no flight moves a whole sector into the mid band. At seed 1 that is 34 sectors plus 15 cells alone, instead of 435 dome chunks. A merged chunk takes the band of its nearest cell and interleaves its cells' importance orders, so a density prefix is each cell's own prefix within one stroke. Every other cell stays a chunk of its own. The modes without class blocks (`write`, `strokeorder`, `paintorder`) sort the merged chunks by their sphere centres. The one lights chunk's centre lies well inside the dome, so it sorts as one unit in front of every dome sector: at the painter view `strokeorder` now paints the dome over the moon and stars, and `paintorder` paints them whole on top, where 670342c mixed the 21 lights cells in among the dome cells. The ground, village and cypress read as before, and `write` is unchanged. The lights and cypress chunks write depth while they draw. The star and moon halo draws between the lights and cypress blocks, so world-stroke overhang paints over it. A batch made with `depthWrite: true` keeps the old `write` policy as its default: the P1 canvas (`?demo=canvas`), whose layers are stepped along the normal. Lone stroke meshes (the teleport arc, the settings panel) keep depth writes. The modes: `write` (the old default: stroke depth writes on, the chunks front to back before the base meshes, no class blocks), `nowrite` (equal to the batch's own default, kept so older URLs parse; the P1 canvas defaults to `write`, so there `?zdiag=nowrite` changes nothing and its strokes still write depth), `strokeorder` (the live depthFunc ALWAYS A/B, depth writes on, which leaves the world strokes under the base meshes), `paintorder`, `nosort`, `noa2c`, `sharp` (alpha-to-coverage kept, with twice the R3 coverage sharpening gain, so a half-pixel rim), `sharp4` (four times the gain, a quarter-pixel rim), `nomip`, `mip` or `freeze` (XR only). It implies the `shimmer` or `zdiag-all` A/B group (`?ab`), so the mode can change at runtime: each switch puts the stroke materials, atlas and order back on the state they were bound with, then applies the new mode. With `?diag`, `__goghDiag().zdiag` is `{ mode, applied, frozen, state, precompiled, precompileMs }`, where `state` is the first band material's `{ depthWrite, depthFunc, alphaToCoverage, alphaTest, sharpGain }` plus the batch's `order` policy and the atlas's `{ minFilter, generateMipmaps, anisotropy }` (null before a batch binds), and `precompiled` counts the programs an A/B group compiled ahead of their first draw. `bun scripts/shimmer-probe.ts <url>` measures per-mode flicker under seeded jitter (docs/verification.md, headset shimmer diagnosis).
- `?ab=<group>`: testing only, honoured in production like `?zdiag`. Activates an A/B group (`src/diag/ab.ts`) at its first variant, and the A/B button (`abCycle`, Controls) cycles it live, wrapping round, with no reload. The groups: `shimmer` (base, write, noa2c, sharp, sharp4, freeze, where base is the nowrite default and `write` the old depth-writing one), `zdiag-all` (base then every `?zdiag` mode), `halo` (on, off), `calm` (1, 0.5, 0.25), `wrap` (wave, base, pingpong, the default wave first) and `vtx` (base, fewer, smaller, sparse, hoist; no implying flag, see the `?ab=vtx` bullet). `?zdiag=<m>` implies `shimmer` when m is in it, else `zdiag-all` (so `?zdiag=nowrite` implies `zdiag-all`), `?nohalo` implies `halo` and `?wrap=<v>` implies `wrap`, each starting at that flag's variant. `?calm` is a setting and implies nothing, but `?ab=calm` starts at the effective calm (the stored calm, or `?calm` over it). When that calm is not one of the variants, it is inserted among them in descending order (0.7 gives 1, 0.7, 0.5, 0.25), so the boot never changes the calm (`calmVariants`). One group is active at a time. `?ab` wins over an implied flag, and the implied flags rank `?zdiag`, `?nohalo`, then `?wrap`. A losing flag stays fixed when the winner drives another setting, and is ignored when the winner drives the same one (`?ab=shimmer&zdiag=nomip`). Every loss goes into one warning. An unknown group warns and is ignored. The bench ignores all of it. Activation precompiles every variant's program: the four stroke programs (base, `ZDIAG_ALPHA_TEST`, gain 2, gain 4) once a batch binds, or a hidden halo once the world builds, so no switch links a program in XR. The `wrap` arms are uniforms on the shipped program, so there is nothing to precompile. `vtx` precompiles its `hoist` program per stroke batch (the `?ab=vtx` bullet). A group named by `?ab` also starts the HUD shown, so its build, font fetch and program land at boot and not on the first click. A group implied by `?zdiag`, `?nohalo` or `?wrap` leaves the HUD hidden until its first switch, because those flags drive byte-compared captures, and that first switch pays the HUD build (`abShowsHudAtBoot`, unit-tested in tests/ab.test.ts). Each switch shows the HUD again, and while a group is active the HUD's last line is `A/B <group>: <variant> (<n>/<count>)`. With `?diag`, `__goghDiag().ab` is `{ group, variants, index, variant }`, or null with no group active, and `__goghDiag().abSwitch` is the last switch's `{ variant, applyMs, frameMs }` CPU cost (the apply, then the apply plus the rest of that frame), or null before one. The `halo` group on a world with no halo pass (the gallery) warns once and its switches do nothing. zdiag binds one stroke batch at a time: a rebind replaces the last. A boot with no A/B flag, the gallery included, builds no group, no HUD and does no per-frame A/B work. `tests/e2e/ab.spec.ts` covers it, with full `shimmer`, `zdiag-all` and `wrap` cycles back to a byte-identical painter view.
- `?ab=vtx`: testing only, the vertex-versus-fill A/B (`src/render/strokes/vertex-arms.ts`, headset protocol in docs/verification.md, vertex cost or fill). It acts on the stroke batch's band materials only, so the arc, panel and portal fly strokes stay at base. The measuring arms cut their target quantity by 30%:
  - `base`: the batch as shipped.
  - `fewer`: each chunk draws 0.7 (`VTX_FEWER_KEEP`) of its unpinned instances, an even share of its importance order (its end in a world or overlay chunk of a nowrite batch, `drawsSuffix` in `src/render/strokes/batch.ts`), and the survivors keep their size. Instances, vertex invocations, primitives and the painted area all fall by about 30%, since strokes write no depth and every fragment shades, so it cuts vertex work and fill together and gaps open. It is CPU-side (`applyDensity` multiplies the band density by the keep share), because a per-vertex hash test would still run every vertex of a dropped instance, the binning pass included.
  - `smaller`: every instance draws, each stroke scaled by sqrt(0.7) (`VTX_SMALLER_SCALE`) on both axes through `uVtxSize`, a uniform the batch's band materials share and the shader multiplies the quad size by (`vec2 size = iSize * sizeScale * uVtxSize`). It is 1.0 outside the arm, and lone stroke meshes keep their own 1.0. The area falls by 30% and the vertex work holds. At about 25 px per triangle the partially covered 2 × 2 pixel quads along each edge mean the fragment work falls by less than the area, and the smaller quads also touch fewer bins.
  - `sparse`: `fewer`'s instances with the survivors grown by 1/sqrt(0.7) (`VTX_SPARSE_SCALE`) through each band's `uSizeScale`, cull radius and fit caps included, so it is the `area` density law at 0.7 on every band: vertex work falls by 30%, and the painted area holds except where a fit cap stops a stroke growing. The total perimeter falls to 0.84, so it also cuts some overshaded edge work. `batch.sizeMultiplier` keeps reporting the plain band size.
  - `hoist`: the `VTX_HOIST` define, so the default program has no hoist code. Projection × (view × p) instead of (projection × view) × (model × p), the identity model matrix dropped, the three varying renormalisations skipped, and the sky's rest field read from two per-instance attributes, `iSkyField` (omega × d, omega · n) and `iSkyWave` (the wave wrap's static phase and fade), 24 bytes per instance, built on the CPU in float64 and zero off the sky. Its pixels differ from base by float rounding (the reordered matrix product and the float64 rest field), plus a sub-percent axis-length change under the motion turn's polynomial cosine and sine, which base renormalises away: 0.0153% of channels move more than 8 levels at the painter view. About 112 scalar ops per ground vertex and 179 to 266 per sky vertex (docs/verification.md).
  - No switch links a program. When the group activates, each stroke batch prepares once, on a microtask after its first frame: it adds the sky attributes to its chunk geometries and compiles its band materials with `VTX_HOIST` on and off (`renderer.compile`). A switch then flips the define on cached programs. A batch that binds later in the session prepares on a microtask after its own first frame, so that frame pays the compile. Until it has prepared it stays on its base program, even under `hoist`, because its chunks lack the sky attributes, and it switches once prepared.
  - With `?diag`, once the group activates, `__goghDiag().vtx` is `{ arm, keep, scale, prepared, program, verticesPerInstance, views, instances, vertexInvocations, drawnAreaM2, drawnSr, drawnSrViews }`: `scale` the arm's linear stroke scale (smaller's or sparse's), `prepared` true once every batch has its hoist program and sky attributes, `program` `hoist` under the define, else `base`, `instances` the drawn instances after the last cull over every batch, `views` 2 in XR (three r186's WebGL XR path has no multiview, so each chunk draws once per eye) and 1 on the desktop, and `vertexInvocations` instances × 4 × views (the quad is 4 indexed vertices). `drawnAreaM2` and `drawnSr` walk each visible banded chunk's drawn strokes at their band size, with each stroke's fit cap applied and `uVtxSize` after it, as the shader does. `drawnAreaM2` counts each stroke once. The world area is dominated by the far dome, so the fill proxy is `drawnSr`: area / d² per stroke inside each view's frustum from that view's eye, summed over the views, with `drawnSrViews` per view. It leaves out the haze growth, the sky-light thin, motion, occlusion and the angle to the eye, so it is an upper bound. It walks every drawn stroke, so a read within 1 s of the last in the same arm reuses it. Headset: `https://gogh-xr.pardev.net/?painting=starry-night&ab=vtx&nogov&hud&diag&fov=1`.
- The depth tie-break key is CPU-side for every stroke geometry: the batch chunks, the teleport arc, the settings panel and the portal fly strokes each carry `iTie` (float, 4 bytes per instance, `src/render/strokes/tie-key.ts`), the top 24 bits of the hash stroke.vert.glsl used to compute per vertex. The arc and the panel rewrite it with their instances. The fly strokes write it once, because their depth test and write are off, so the key cannot change a pixel. A ranked stroke off the backdrop keys on its size hash, every other stroke on its position hash, which the backdrop rank reads too. The shader has no hash left (about 49 scalar ops per vertex saved). The hash is integer maths on the float32 bits, so the key equals the old one exactly (`tests/strokes-tie-key.test.ts`) and every boot is byte-identical.
- `?densitylaw=area|count`: testing only, trimmed and lower-cased; any other value keeps `area`. The governor's density-shed size law (`GovernorConfig.densityLaw`, read by `startGovernor` from the flag). `area` (the default) grows a shed band's survivors by sqrt(from / to), so the painted area holds. `count` keeps their size, so a shed cuts instances and area together, the lever if the headset reads fill-bound or both (the `area` law already cuts vertex work alone, as `sparse` shows). It costs coverage: at a simulated governor level 4 it leaves 16 of the 24 coverage poses over the 0.5% bar, against none under `area` (docs/verification.md, vertex cost or fill). Under `count` each density band holds apart after a no-gain, since a band's step then cuts its own fill and vertex work; under `area` the bands share one `density` hold. It changes only what a shed does, so a session that never sheds draws the same. Headset: `https://gogh-xr.pardev.net/?painting=starry-night&densitylaw=count&hud&diag`.
- `window.__goghBands({ density, size })`: e2e builds only (`vertex-arms.ts`). Sets every stroke batch's band densities and size multipliers, so a spec can draw a governor level on the desktop with `?nogov`. `tests/e2e/vtx.spec.ts` uses it for the level 4 coverage sweep (`GX_VTX_SWEEP=1`).
- `window.__goghVtxSize(value)`: e2e builds only (`vertex-arms.ts`). Overrides `uVtxSize` until the next arm switch, so the vtx spec can show its measured `smaller` check fails with the size factor forced to 1.
- `?fov=0|0.5|1`: testing only, honoured in production like `?slow`. Pins the XR session's fixed foveation (`applySessionSettings` in `src/xr/session.ts`) in place of the default `FOVEATION` (0). Any other value means no pin. A running governor re-asserts its own foveation level on every judged frame, so the pin holds only with `?nogov`. The vtx headset protocol runs its arm cycle at `&fov=1`, the foveation of the governed level-4 frame, and at `&fov=0`.
- `?update`: on, off or absent. The build poller (P7.1, see Updates). Absent polls only in a production build, `?update` also polls in an e2e build, and `?update=0` turns it off in any build.
- `?nogov`: boolean, testing only. Keeps the quality governor off, so densities stay fixed. The e2e specs that check stroke counts in XR use it, because headless Chromium's 60 Hz vsync already overruns the 72 Hz budget. Like `?slow`, it is honoured in production builds on purpose, since it is URL-only and affects only the page that sets it.
- `?painting=<id>`: boots straight into a painting's world from the registry (`src/paintings/registry.ts`), parsed like `?demo` (trimmed, lower-cased). Only `starry-night` is live: it builds the Starry Night world (`src/paintings/starry-night/index.ts`), binds its stroke batch to the governor, drops the bare scene's placeholder ground and grid, and stands the locomotion rig on the module's `spawnPose()`, which for Starry Night is the painter's spot (0, 0, 0) facing -Z, so the desktop eye is the painter's eye (0, 1.6, 0). `?painter` replaces that start with the painter camera. The rig carries the spawn in XR too, so a non-origin spawn needs no offset reference space. The `WorldHandle` that `build()` returns carries the batch, the built world's `ground` (`heightAt`, `normalAt`), `boundaryFactor(position)` and `blocked(x, z)` for P3 locomotion. Starry Night's `blocked` is true on a house's walls or the church's tower or nave, grown by 0.3 m (`src/paintings/starry-night/footprints.ts`). Its `volumes` and `treeBlocked` cut arcs at buildings and reject landings in the cypress crowns (see Locomotion). An unknown or coming-soon id logs a warning once and boots the gallery, where that painting hangs, never the bare scene (`tests/boot-mode.test.ts` covers every non-live registry entry). The id is otherwise ignored, so an explicit `?scene=bare`, `?strokesTest` or `?demo` after it still wins. A live id whose world cannot start (its module import does not settle within `WORLD_IMPORT_TIMEOUT_MS`, or the import or build throws) warns, raises the `world-failed` notice and boots the gallery instead (`src/boot-world.ts`, `bootWorldWithFallback`); a build that threw is disposed first (Starry Night's `build` also releases what it added to the scene when it throws, since a rejected build is never disposed by its caller). If the gallery fails too the scene stays empty, with the notice. The bench ignores it. With `?diag`, `__goghDiag().world` holds `{ painting, seed, debug, counts, lightRankTies, total, times: { decodeMs, generateMs, scatterMs, batchMs, buildMs }, cache, strokes }`, where `counts` is per stroke layer plus `haze` and `eaves`. In `counts`, `sky` is the dome. `eaves` counts the eave underside copies (`src/paintings/starry-night/eave-undersides.ts`), 10,053 at seed 1, which `building` leaves out. They are generated on every build outside the scatter cache and appended after the haze: each roof stroke whose painted footprint reaches past the wall line onto the 0.25 m overhang gets one copy facing down, mirrored through the slope's plane, so the overhang still shows paint from the ground below it. The roof and church base meshes close each overhang from below with a soffit strip (`pushGableSoffit`) inside the same mesh. Nothing in the world draws both faces, and the copies add no chunk or draw call. `star` and `moon` are the static moon and star discs of `src/world/sky-lights.ts`, which are generated on every build outside the scatter cache, appended after the scatter and before the haze, and drawn in the backdrop's front tier over the dome. They are brushed like the dome around them (its stroke size, brushes and flow direction). The stars split finer only at colour edges such as their cores. The moon keeps the dome's stroke size, with finer strokes drawn on top only along the crescent's edges. Both thin out over a rim band to 1.5 anchor radii. Their colours come from `lights.webp`, the bake's full-resolution scan around each anchor, and from frame.webp past it. The batch pins them: they are the one `lights` chunk, which draws all of them at every band density, so governor shedding thins only the dome around them. `lightRankTies` counts the light strokes that share a front-tier rank with an overlapping one, judged in metres on the dome (0 at seeds 1 and 2, and a unit test finds no same-rank overlapping pair from the stored positions and sizes). Every haze stroke carries `SKY_LIGHT_CULL_FLAG`, and the stroke shader judges it per view, from that view's eye, against each disc's cone (`src/render/strokes/sky-light-cull.ts`). It collapses a stroke that could reach over a disc, and past the cone it shrinks the drawn size so each quad's area, and approximately the haze's coverage, ramps from 0 to full over a feather of `SKY_LIGHT_FEATHER` (3) anchor radii plus one haze half diagonal, so the haze has no hard rim in front of the moon or a star. The draw calls and instance counts are unchanged. `cache` is `hit`, `miss` or `bypass`, and `strokes` is the batch stats. No `?seed` means seed 1.
- `?scene=bare`: boots the bare scene (placeholder ground and grid, no world) instead of the default gallery, trimmed and lower-cased. Any other value is ignored. Honoured in production. `?bench`, a live `?painting` id, `?strokesTest` and `?demo` all win over it. It is the only way to reach the bare scene. The e2e specs that test the bare scene's input, vignette, arc and motion pass it.
- `?bare`: boolean, honoured only together with `?diag` and a world. Every base mesh and the clear colour turn flat magenta `#ff00ff`, and the stroke batch is hidden. The coverage sweep uses it to calibrate: the view reads 100% magenta.
- `?coverage`: boolean, honoured only together with `?diag` and a world. Like `?bare`, but the strokes still render, so every magenta pixel is one the strokes leave bare. `tests/e2e/world-coverage.spec.ts` sweeps 24 poses with it and fails a pose over 0.5% bare. `?bare` wins when both are set.
- `?painter`: boolean, honoured only together with `?diag` and a world. Once the world module loads, and before the world builds, the desktop camera takes the world's `painterCamera()` (`src/paintings/world-module.ts`). Starry Night's comes from `src/paintings/starry-night/canvas-camera.ts`: eye (0, 1.6, 0) facing -Z, pitched up by `CANVAS_PITCH`, vertical FOV 60° and aspect `CANVAS_ASPECT`, which it keeps on a resize. The frame is then exactly canvas uv [0, 1]², so capture at the canvas aspect (`CAPTURE_SIZE`, 1280 × 1028) to avoid a stretch. Canvas uv is the painted canvas with the mat excluded: the 3840 × 3041 scan inset by `COLOR_INSET` (3750 × 3011, so `CANVAS_ASPECT` is 3750 / 3011), the one extent the colour sampling, `flow.png`, `regions.png` and `regions.json` share. It is placed like `__goghPose`, so ground follow leaves it alone until WASD moves it. The P2.8 fidelity metric (`scripts/fidelity.ts`, `tests/e2e/fidelity.spec.ts`) captures through it.
- `?diag` also installs `window.__goghPose(x, y, z, yaw, pitch)`, which puts the desktop eye exactly at that position and heading through the rig (rig at y − 1.6, rig yaw, camera pitch). Yaw 0 faces -Z, and pitch ±π/2 looks straight up or down. Ground follow is suspended for a placed pose until the next movement input, then eases the rig back onto the ground, because the coverage poses carry absolute eye heights.
- `?seated`: boolean, seated mode (`src/locomotion/`). - The quality governor (`src/render/governor.ts`) runs in XR for every scene with a stroke batch (the default gallery, `?strokesTest`, `?demo=canvas`, `?painting=starry-night`), never for `?bench`. The boot modes are exclusive (`src/boot-mode.ts`, see Gallery): `?painting` with a live id wins over `?strokesTest` and `?demo`, and warns once that it ignored them. Its target comes from the quality (see Settings): the default `adaptive-72` and `beauty-72` target 72 Hz, which the session requests at its start, so an adaptive governor (the `qualityLevel` `'auto'`, which the user must pick since the default is the fixed level 5) judges against the 13.9 ms budget from its first judged frame and never requests a rate. At the default fixed level the governor applies its steps once and judges nothing (see the fixed level below). `adaptive-90` (also `?hz=90` and `?hz=120`) targets its rate and keeps the 72 Hz fallback below. Its budget follows the frame rate the session reports, so a start request that is missing or fails leaves the budget on the reported rate, and the 72 Hz fallback commits only once `updateTargetFrameRate` resolves. It sheds foveation and fb scale first: on the headset (2026-11-06, `docs/verification.md`) foveation 0.5 measured -16%, while density bought nothing. The frame is GPU-bound, not CPU or draw-call bound, and pixel count alone does not explain it: 0.49x the pixels plus foveation 1 reads 18.71 ms against 17.2-18.1 ms for foveation 1 alone, and the GPU profiler puts about 54% of shading time on vertices (85M polygons/s of about 25 px). The order is foveation 0 to 0.5 (step `foveation`), fb scale 1 to 0.85, foveation to 1 (step `foveation-max`), then far, mid and near density. The foveation steps are not yet verified on a headset. Foveation goes through `renderer.xr.setFoveation`, which sets the projection layer's `fixedFoveation` live, and every judged frame re-asserts it if three reports another value. Density goes last: under the default `area` law (`?densitylaw`) each density step grows the band's stroke size to keep its coverage, so it keeps the painted area, and on the headset it bought nothing measurable. Under `count` the survivors keep their size. A shed whose next window still overruns and is not at least 3% faster is undone at once (a `no-gain` event), and that step is held for 30 s, or until the reported frame rate changes or the session is interrupted. Each further hold of the same step, from no-gain or from recovery, doubles: 30, 60, 120, 240, then 300 s. A frame-rate change or a new session restarts the doubling, and a shed that pays restarts it for that step. The two foveation steps hold apart, so a 0.5 that reads as no-gain does not block 1. Under the default `area` law the density bands share one hold, `density`: under the size law one band's no-gain predicts the others', so a density no-gain holds all three. Under `count` each band holds apart. A held step counts as nothing left to shed, so in `adaptive-90` the 72 Hz request still follows 3 s of overrun. A density step that would cut under 3% of the drawn strokes is skipped. Once the frame has overrun for 5 s with nothing left to shed and no 72 Hz request left to make (the session already runs at 72 Hz, or the request was applied or failed), it restores the top shed step (a `recover` event). If the next 2 s of windows overrun more than 3% worse than that overrun stretch, it sheds the step again (`recover-back`) and holds it from recovery (30 s, doubling). Otherwise it keeps the restore and holds the step from shedding (30 s, doubling). A frame no step helps therefore regains most of its shed steps (in simulation it settles within about three steps of full quality, up to 2.9 at worst over 120 s), and one that needs its sheds keeps its shed level. With `?diag`, `__goghDiag().governor` shows its mode, target, `densityLaw` (`area` or `count`), reported frame rate, rate request state, level, densities, framebuffer scale, foveation (0, 0.5 or 1), last window mean, notice, `judging`, `noGainHeld` (holds against shedding), `recoverHeld` (holds against recovery), where a hold is a step name or, under `area`, `density` for all three bands, and a bounded history of shed, restore, shed-back, no-gain, recover, recover-back and rate events. `judging` is true only while a visible XR session presents. Desktop frames are never judged. `fbScale` is the requested scale. `fbScaleApplied` is the scale the device applied, measured from the returned viewport widths, and null until measured. IWER ignores the request, so it reads 1 there. Quest Browser ignores it too on the projection-layer path three 0.186 takes there (`fbScalePath` `projection-layer`, `fbScaleApplied` 1 at a requested 0.85), so on the headset the fb-scale step buys nothing and the no-gain rule holds it.
- Fixed quality level (the `qualityLevel` setting, see Settings): `GovernorConfig.fixedLevel` N builds a machine that sheds the first N steps of its own shed order at creation (`nextShed` with no drawn counts) and then never judges, so it makes no shed, restore, no-gain, recover or rate event, and no rate request. The frame rate still follows the quality as above. `qualityLadder(mode)` lists the steps: foveation 0.5, fb 0.85, foveation 1, then far, mid and near density, each band by 0.7 down to its minimum. The drawn floor and the 3% yield skip depend on drawn counts, so the ladder skips only a step that cannot apply, which is why it keeps the default mid step 0.216 to 0.2 that the adaptive machine can skip (when it yields under 3% of the drawn total). The default modes have 16 levels (3 + far 4 + mid 5 + near 4) and beauty has 18 (3 + far 6 + mid 5 + near 4), from the max-beauty start densities. `tests/governor-fixed.test.ts` checks that the ladder equals the adaptive machine's shed order. The runtime reads `deps.fixedLevel` every frame, before the judging check, so a change applies on the next frame in XR and on the desktop. A change rebuilds the machine: a fixed one at the new level, or for Auto an adaptive one from the mode's start levels, as at a new session. The rebuild keeps the session's mode and the rate asked of it, so Auto after a 72 Hz fallback in `adaptive-90` stays at 72 Hz and asks for no rate, where a new session would request 90 again (`tests/governor-fixed-runtime.test.ts` pins it). A session start or end rebuilds at the current level. After each reveal frame `nextRevealQuota` aims it at 4 ms of render time (`REVEAL_BUDGET_MS`) by at most ×2 up and ÷2 down, never below the old fixed 8192 (`REVEAL_MIN_STROKES`), so the reveal is never slower than it was before the budget. `revealCost` prices the new strokes as the reveal frame's `renderMs` over the frame before, which already drew every chunk revealed so far, and never below the lowest price per stroke any reveal frame has shown against the frame before the first reveal (the `show` frame, which draws the world but none of its strokes), so a one-off slow reveal frame stops counting once a cheaper one follows. The view never holds still through the build (`src/portal/wait-motion.ts`). In the fly style the strokes swirl where they hover: each turns about an axis through the eye, so it keeps its distance and never looms. The axes are 32 irregular vortices (`planSwirl`): 8 groups, each with its own centre (an axis through the eye within 0.6 of the strokes' half-extent of their mean direction, the half-extent at least 0.45 rad, so the cloud overhangs the frame), tilt, vortex offset (0.15 to 0.6 of the half-extent along each tilted axis), radius (0.3 to 0.6 of the half-extent) and rate (a core turn per 2.5 s at a 0.3 rad half-extent, ±30%, slower in proportion for a wider spread, so the strokes cross the view at about the same speed), and a solid-body core of 0.4 of the radius with the sky's inverse-square fall-off outside it. Each group is 4 vortices mirrored about its own centre, the mirrors' spins flipped (a shared centre made the cloud a four-lobed rosette with a hole on the mean direction), and the strokes hover in slots of eights: one stroke's place, the place opposite it on its circle, and the images of both, each slot then filled by the stroke whose own view direction is nearest, so the cloud keeps the painting's colours roughly where they were. Each frame adds at most 250 ms (`STALL_FRAME_MAX_MS`), so the first frame after a paused loop (the Meta button, a doff) cannot give up a healthy build. The counter-flow (`src/motion/sky-counter-flow.ts`) is the share of nearby pairs, centres within 2° of each other from the painter's eye, with one stroke forward and the other returning. Up to 4000 drawn sky strokes, evenly spaced, are the centres, and every drawn sky stroke is a neighbour. It counts returning flags only, so the wave's fade does not change it. On seed 1 at `?motiont=3.7` it is about 0.5 under pingpong, 0.034 under wave at the default 2 waves per turn (0.043 at 3) and 0 under base. `tests/e2e/ab.spec.ts` checks that a no-flag boot draws byte for byte as `?wrap=wave` at 2 waves per turn, and also checks the GPU's own formulas at fixed phases (`?motionphase=0&motionlayers=sky&ab=wrap&wrap=base`, starting at base): pingpong at f = 0.25 draws byte for byte as base at f = 0.5, and pingpong at f = 0.125 as base at f = 0.15625 (tau −2.75 s for both). Under `?coverage` it cycles to wave and checks the dome stays covered. It also boots `?wrap=wave` at the default and at `&waveturns=3`, and checks that the two report the same program count and their own turns and draw different skies. A count cannot tell a uniform from a define, so the unit tests in `tests/motion-variants.test.ts` pin the uniform-only design: the stroke material's defines and shader source are unchanged by `setWaveTurns(3)`, and `uWaveTurns` appears only in its declaration and the wave branch's loop. `tests/e2e/motion.spec.ts` block-matches the wave's moved sky against the mirror's prediction at each sky patch's own turns, on a grid clear of the star and moon rings.
- `?noanim`: boolean. Freezes the motion clock (`src/motion/clock.ts`, P4.1): `uTime` holds and the motion gate closes for every layer, so every stroke draws at rest. Shot and fidelity captures use it, and two `?noanim` shots taken apart in time are pixel-identical (`tests/e2e/motion.spec.ts`).
- `?calm=0..1`: the motion calm. For the session it overrides the stored calm and is never written back. Parsed like `?slow`, clamped to 0-1, and a missing or malformed value means 1 (full motion). Calm scales every motion's speed on the CPU (`uTime` advances by dt × calm, so a calm change never jumps a stroke) and its offsets, turns and ring brightness in the shader, once, in `src/motion/motion.glsl`. The wrap envelope that shrinks a looping stroke is not scaled. At 0 the time holds and the gate closes, as with `?noanim`.
- Motion (P4.1) is computed in the vertex shader from the shared uniforms `uTime` (seconds, wrapped at 3600), `uCalm`, `uFreeze` and `uMotionLayers`, plus each instance's layer (`iMeta.y`) and phase byte (`iMeta.z`). Every stroke material shares `motionClock`'s uniform objects. `motion.glsl` is spliced into `stroke.vert.glsl` at its `// #include motion.glsl` line by `spliceGlsl` in `material.ts`, and `src/motion/motion.ts` mirrors its gate and dispatch. `uMotionLayers` holds one bit per layer whose motion runs: `MOTION_LAYERS` (the sky, P4.2, the stars and moon, P4.3, and the cypress, P4.4), plus the reactive bit (P4.5), and 0 while frozen or at calm 0, so a still stroke outside the reactive box pays two ANDs, the box test and a branch. The app clock starts with every layer closed, and main.ts opens `MOTION_LAYER_MASK` only when a world boots, so the P1 canvas demo, `?strokesTest` and the bench, whose strokes share the sky layer, stay static. A layer's motion returns a `Motion` struct (centre offset, turn about the stroke normal, size gain, brightness), each 0 at rest. The shader multiplies the stroke's colour by 1 + brightness inside the gate. `motionOffset` multiplies the offset, turn and brightness by calm once. The gain is a loop's wrap envelope, so it runs at full depth whenever the gate is open and a stroke always shrinks to nothing as it jumps back, at every calm. The sky's default `wave` wrap and `pingpong` never jump back, so they keep a sky stroke at full size, and only `?wrap=base` shrinks it (Motion A/B variants). With `?diag`, `__goghDiag().motion` is `{ time, delta, calm, frozen, layers }`, where `delta` is the seconds the last frame advanced `time` by (the frame step times calm: 0 while frozen, at calm 0 and while `?motiont` pins the time) and `layers` is the clock's open mask before frozen and calm close it.
- Sky swirl (P4.2, `src/motion/sky-swirl.ts`): every sky-layer stroke, the boundary haze included, moves along a field on the sphere of directions from the painter's eye: four Rankine-style vortices (the central double swirl, and eddies round the moon and the large lower-left star, authored under `vortices` in `assets/bake/starry-night/regions.json`, which the bake ignores) plus a slow drift about the vertical. Each stroke sweeps a short arc over an 8 s loop (3600 / 450) and turns with the flow. Under the default `wave` wrap it travels ahead and back at full size (Motion A/B variants). Under `?wrap=base`, the P4.2 wrap, it sweeps forward only and shrinks to nothing at the wrap, over the first and last 6% of the loop (`SKY_SWIRL_FADE`). Its displacement is at most `SKY_SWIRL_MAX_ANGLE` (0.034 rad) times its distance from the painter's eye, `SKY_SWIRL_REACH` (about 4 m) on the dome. At build the batch computes each sky stroke's exact reach, half a loop at its own speed (`skySwirlReach`), and each frame grows a chunk's cull sphere by its largest reach times calm while the sky's gate is open, and by nothing while it is closed, so under `?noanim`, at calm 0 and in the P1 canvas demo the cull spheres are the rest spheres. While the gate is open the haze's sky-light thin widens each stroke by its own reach, so a moved haze stroke never covers a disc.
- Star and moon rings (P4.3, `src/motion/sky-rings.ts`, mirrored by `src/motion/sky-rings.glsl`): each of the 11 stars and the moon sends a wave outward from its anchor's centre, `ringBump(fract(t / period + phase − r / outer))` with ringBump(f) = (4f(1 − f))², so one crest crosses the rim per period. Star periods are 3600 / round(3600 / T) with T spread over 3-7 s, and the moon's is 10 s. A crest pushes a star or moon stroke radially by swell × wave × hat(r), where hat(r) = (r − inner)(outer − r) / (outer − inner) and `outer` is the rim at 1.5 anchor radii (`anchorReach` in `src/world/sky.ts`). No moved centre passes the rim, so the sky-light cones are not grown. The moon's `inner` is its own radius, so its crescent neither moves nor brightens, and only its strokes in the band from that radius to the rim ripple. A crest also brightens a stroke from `inner` out by up to 35% for a star and 20% for the moon, and calm scales the push and the brightening. The gain is 0, so a ring never shrinks a stroke. A light stroke's phase byte is its anchor's index (the moon's strokes ignore it), so the shader finds its ring with one const-array index. `SKY_RING_REACH` (about 1.67 m) bounds every ring displacement, and the batch grows a chunk's cull sphere by calm times the largest reach among its strokes on open layers (sky, star, moon). The front-tier rank picker (`RankPicker` in `src/world/sky-lights.ts`) widens each pair's overlap test by both strokes' ring reach, so no two strokes that share a rank overlap as the rings move them.
- Star and moon halos (P4.3, `src/render/sky-halo.ts`): one instanced mesh of 12 soft additive glows, one per anchor, on the dome's tangent plane at the anchor. A star's is a disc of radius 0.6 × the rim, brightest at its centre. The moon's is a band over 1.0-1.5 of its circle, brightest at 1.25, 0.05 at rest plus up to 0.07 on a crest, drawn as an octagonal ring whose hole covers the crescent, so no halo light lands on the crescent. It is the world's only blended pass: one-one additive, depth-tested, no depth write and never frustum-culled, so it is exactly one draw per view, two in XR without multiview. The Starry Night world draws it in the opaque queue at `batch.orderBeforeClass('cypress')`, after the lights and before the cypress and world strokes, so their overhang paints over it (docs/verification.md, nowrite default, fix round 2). Built with no render order, it is transparent and draws after every opaque object. Its depth is pinned at `SKY_HALO_NDC`, in front of the backdrop tiers and behind any world geometry nearer than about 246 m. While the star or moon gate is open it swells by up to 12% and carries travelling rings with its anchor's wave. Under `?noanim` and at calm 0 it draws its rest glow. It is hidden under `?bare`, `?coverage` and `?nohalo`. At the painter view it covered 9.4% of the frame at rest and 11.4% at full swell, measured before the 2026-11-09 canvas uv change and not re-measured since. With `?diag`, `__goghDiag().halo` is `{ visible, halos }`, where `halos` holds `{ size, centre, phase, ring }` per anchor: `centre` is the band's peak radius and `size` its half-width, in metres. They come from the TS mirror on the CPU for the clock's current uniforms, not from the GPU.
- `?nohalo`: boolean, testing only, honoured in production like `?zdiag`, since it is URL-only and affects only the page that sets it. The world draws no halo pass, for a cost A/B and for the e2e shots that read the ring strokes alone. It implies the `halo` A/B group at off, so the A/B button turns the pass back on (`WorldHandle.setHalo`). The halo diag still reports the mirror's state, with `visible` false.
- Cypress flame (P4.4, `src/motion/cypress-flame.ts`): every cypress stroke climbs its face plane's steepest ascent, `up = Y − n·n.y` (unnormalised, so it never descends), over a ±0.15 m arc per 4 s loop (3600 / 900), wraps with its phase byte and shrinks to nothing at the wrap, over the first and last 5% of the loop. The arc tapers to 0 over the top 15% of each mass. Each lobe sways along `Y × n` by two travelling sines in y (2.4 s and 1.5 s) phased by its lobe id, up to 0.14 m times the square of the stroke's normalised height. The scatter bakes the lobe id (top three bits) and the height, rounded up to a 1/30 level (low five bits), into the stroke's colour alpha byte, which the default path never reads; 255 marks a stroke with no flame data, which stays at rest. The batch grows a cypress chunk's cull sphere by calm times its strokes' largest exact reach, `sin φ × √(rise² + sway²)`, at most 0.18 m on seed 1 (measured before the 2026-11-09 canvas uv change).
- Reactive strokes (P4.5, `src/motion/reactive.ts`): strokes on every layer make way around the head and both controllers, behind their own gate bit, `REACTIVE_MOTION_BIT` (bit 6 of `uMotionLayers`, above the six layer bits), so the per-layer motions stay independent of it. `MOTION_LAYER_MASK` includes it, and `?noanim` and calm 0 close it with the rest. The disturbers are the head (world position of the camera inside the rig, which in XR holds the last frame's head pose) and the target-ray spaces of both controller slots, used only while presenting and tracked. On the desktop the eye is the only disturber. Each carries its velocity relative to the locomotion rig from the last frame, clamped to 3 m/s (Q41): the rate of change of its rig-local position (the rig's world matrix is passed to `frame` and its inverse applied), rotated back into world axes by the current rig rotation. Walking, sprinting, flight, smooth and snap turns and teleport move the rig and not the rig-local position, so they add nothing to any velocity, and only physical motion inside the rig does: a hand waving or reaching, or the head leaning or walking in room scale. Paul ruled that locomotion must not push strokes. The head's rig-relative velocity at its 0.4 strength is a controller assumption, not a ruling. Positions stay world: the static proximity push `0.6 × (p − d)`, the wake sample positions and the box use them, so strokes still part round a hand held near a wall as the rig glides past, and a hand waved while walking leaves its wake where it was waved. Only the velocity terms (the `0.04 s × velocity` drag, the wake weight's speed over 1.5 m/s, and the 3 m/s and 15 m/s clamps) read the rig-relative speed. The desktop eye is fixed in the rig, so its velocity is always 0 and WASD leaves no wake. Locomotion counts discontinuities (`discontinuities()`): a teleport jump, a snap turn, `spawn`, `setPose` (so `__goghPose`), and each `markDiscontinuity`, which main.ts calls on an XR reference-space `reset`, the system recenter. When the count changes, every disturber's history restarts at the new pose with velocity 0, so no wake or drag is drawn across the jump. Teleport and snap turn already give no velocity spike, because the rig-local position does not jump, so the reset is the backstop for them and the only guard for the reference-space `reset`, which moves the disturbers inside the rig. A frame-to-frame rig-relative step faster than 15 m/s does the same for that disturber alone, a backstop for a re-tracked controller. The app's own recenter (P5.3) counts one too, through `faceYaw`. The tracker's time is `frame.predictedDisplayTime` when the XR frame has one, else the callback time (`trackerTime`, `src/motion/tracker-time.ts`), because the headset predicts controller poses for that time. The head pushes at strength 0.4 and a controller at 1, for comfort round the viewer's face. Each disturber keeps 8 wake samples at least 150 ms apart, a 1.2 s window that spans the decay's own time constant. A sample's weight is the strength times its speed when taken over 1.5 m/s (capped at 1), times a fade-in over its first 60 ms (its own constant, not the interval), times exp(−age / 1.2 s) tapered smoothly to 0 over the window's last quarter (0.9-1.2 s, from a weight of about 0.47), so a still hand leaves no wake and no sample pops in or out. Within a 0.6 m radius, with the falloff (1 − x²)², each disturber pushes a stroke by strength × falloff × (0.6 × (p − d) + 0.04 s × velocity), 0 at the disturber itself and at most 0.103 m for a still hand, and each wake sample turns it about its own normal through the sample by weight × 0.12 rad × falloff, so strokes curl round the trail. The sum loses its part along the stroke normal, so strokes slide along their surface, and is clamped to `REACTIVE_REACH` (0.25 m), with the turn capped at 0.5 rad. The gain is the push's areal stretch in the stroke's tangent plane, J ≈ (1 + a)(1 + a − tr M), exact for one disturber: the stroke grows by √J − 1, never below 0 and capped at 1 (2×), so strokes the push spreads apart still cover the surface (ruling R-P4o). One hand at the surface grows the strokes at its foot point 1.6×. Calm scales the stretch with the push, and the gain combines with the layer's gain as a size factor. There is no phase, so the star and moon phase bytes are not read. Calm scales the offset and the turn. Displacement is a pure function of the rest position and the current field, so displaced strokes spring back as the wake decays and the hand leaves. Each frame the CPU sends the box round every weighted disturber and wake sample, grown by the radius (`uReactiveCentre`, `uReactiveHalf`, empty with negative half extents), and the vertex shader tests the stroke's rest centre against it before any reactive maths. The shader reads `iPosition` as world space, which holds because every batch group and chunk sits at the identity. While the bit is open, a chunk whose box round its strokes' rest centres overlaps the reactive box (closed bounds, a superset of the shader's strict test) grows its cull sphere by calm × 0.25 m on top of its layer reach and its half-diagonal term by the growth cap (2×), tested on the CPU per chunk per frame (P4.6). No other chunk can hold a moved stroke, so with no stroke near a disturber the cull is the P4.4 one: at spot ahead in a 1280 × 720 view with every layer open the batch drew 260,604 strokes, as with the reactive bit closed, where growing every chunk drew 262,478 (measured before the 2026-11-09 canvas uv change). A haze stroke inside the box widens its sky-light thin by the same reach. The stretch growth comes after that thin, so a grown haze stroke can reach past the extent the thin judged. It still stays out of the disc cones, because a haze stroke grows only within 0.6 m of the head or a hand, at most about 1.4 m from the eye, inside its own rest half-diagonal of at least 1.62 m, where the thin is already its coarse hemisphere cut. The teleport arc has its own `uMotionLayers`, always 0, so it never moves and still shares the batch's program. With `?diag` outside `?bench`, `__goghDiag().reactive` is `{ frames, discontinuity, resets, disturbers, box, boxStrokes }`: `frames` counts tracker updates, `discontinuity` is the last locomotion count read and `resets` how many times it changed, each disturber (head, slot 0, slot 1) is `{ tracked, position, velocity, strength, wake, wakeWeight, wakePeak, jumps }` (`wake` the samples held, `wakeWeight` the sum of its sample weights in `uWake`, `wakePeak` the strongest single one, which unlike the sum does not depend on how many samples the frame timing took, `jumps` the resets by the 15 m/s backstop), `box` is `{ min, max }` in world space or null when empty, and `boxStrokes` counts the drawn strokes whose rest centre is inside the box, the ones that pay the reactive loops (null before a stroke batch binds). It scans every chunk on each read.
- `?motionlayers=<list>`: testing only, honoured only in `--mode e2e` builds. A comma-separated list of stroke layer names (`sky`, `star`, `moon`, ...) and `reactive` (the reactive gate bit), trimmed and lower-cased, whose motion stays open. It can only close layers: the clock's mask is the default motion mask AND the list, so `?motionlayers=sky` moves the sky alone, with the rings and the reactive motion still, and `?motionlayers=reactive` runs the reactive motion alone. Unknown names add nothing, and an empty list closes every layer. `__goghDiag().motion.layers` shows the mask in force.
- `?motiont=<s>`: testing only, honoured only in `--mode e2e` builds. Pins the motion time `uTime` at s seconds (wrapped at 3600) with the gate open, so a motion e2e is deterministic. The pin lives on the CPU in main.ts behind `import.meta.env.MODE === 'e2e'`, so a production build drops it and the shader reads nothing extra. With a pin, e2e builds also install `window.__goghMotionT(t)`, which moves the pin to t seconds without a reload, so one boot can sweep many times (the P4.6 coverage phase sweep and ring tests). `?noanim` still freezes and calm 0 still closes the gate. A negative or malformed value is ignored.
- `?motionphase=<f>`: testing only, honoured only in `--mode e2e` builds. Gives every stroke the motion phase f, wrapped to [0, 1), in place of its phase byte, so under `?wrap=base` or `pingpong` a pinned `?motiont` moves the whole sky coherently and the e2e can measure its displacement by block matching (`tests/e2e/motion.spec.ts`, which boots `?wrap=base` for it). Under the default wave the phase comes from each stroke's direction and the pin sets only its jitter. The star and moon rings (P4.3) ignore it: their phase is per anchor, and their phase byte names the anchor. main.ts calls `pinMotionPhase` before any material is built, and the materials carry it as the `MOTION_PHASE_PIN` define, so a production material never has it. e2e builds also install `window.__goghSkyShift(u, v, calm, time, phase, wrap)`, the TS mirror's predicted canvas shift (under `wrap`, base when omitted, which is not the app's default wave) of the dome stroke at canvas (u, v down) (`src/diag/swirl-probe.ts`), and `window.__goghRingShift(k, u, v, time)`, the mirror's shift and brightening at calm 1 of the same dome point under ring k of `SKY_RINGS`, with the ring's canvas centre and rim, and `window.__goghHaloGlow(k, u, v, time)`, the mirror's additive brightness (before the tint) of halo k at that canvas point at calm 1, and `window.__goghMoonDisc(points)`, the moon disc's rim (its `anchorReach(anchor, 1)` circle on the dome's tangent plane) as `points` canvas [u, v-down] pairs, for the P4.3 clip check in `tests/e2e/motion.spec.ts`, because Playwright cannot load `sky-swirl.ts`, `sky-rings.ts` and their regions.json import. A negative or malformed value is ignored.
- `?mute`: boolean. Starts the audio mixer's master gain at 0 (`src/audio/`). The music and SFX buses keep their levels, and the context still unlocks on the first gesture. `__goghDiag().audio.muted` reads it.
- `?shot`: boolean, honoured only together with `?diag`. Enables `window.__goghShot()` (canvas PNG data URL) and `preserveDrawingBuffer`. It takes no value.
- `?strokesTest`: boolean. Builds the deterministic stroke-engine test scene (`src/render/strokes/test-scene.ts`): 6000 strokes over 14 chunks, including a sky wall at z = -2 and a building wall behind the viewer at z = +6. It registers `strokes` in `__goghDiag()`, reporting `{ chunks, visibleChunks, total, visible, atlasMs }`.
- `?demo=canvas`: the P1 test canvas (`src/demo/canvas/`). It repaints the painting in about 200k strokes on a 4 × 3.17 m plane centred at (0, 1.6, -2.55), facing the XR origin. Like every scene without a world, the rig starts at the origin. Placement is deterministic for `?seed`, and no seed means seed 1. `&count=N` sets the stroke target instead of 200k, rounded and clamped to 10k-1M, so `&count=325000` draws the P0 default budget and `&count=500000` the max-beauty one. Placement lands within a few percent of the target (325000 gives 325,261). A non-numeric or malformed value means the default. It registers `canvas` in `__goghDiag()`: `{ seed, count, decodeMs, placeMs, batchMs, buildMs, strokes }`, where `strokes` holds the batch stats. Capture the P1-A2 shot with `bun scripts/capture-shot.ts "http://localhost:PORT/?diag&shot&demo=canvas&noanim&seed=1" docs/shots/p1-canvas.png --wait canvas`.

## Controls

`src/xr/input.ts` folds the XR gamepads (xr-standard mapping only) and the keyboard and mouse into one `Actions` frame per animation frame. `src/xr/input-keyboard.ts` captures the keys and mouse buttons. Locomotion (`src/locomotion/`) consumes `move`, `sprint`, `turn`, `teleportAim`, `teleportCommit`, `flightToggle` and `vertical`. Sticks use a 0.15 radial deadzone, and the frame carries `dt` clamped to 0.1 s.

| Action | XR | Desktop |
| --- | --- | --- |
| `move` (x right, y forward, magnitude ≤ 1) | left stick | WASD |
| `sprint` (level) | none | Shift |
| `turn.x`, and `turn.snap` once per push past 0.7 with X dominant, re-armed once the whole stick is back inside the deadzone or Q/E is released | right stick X | Q (left), E (right) |
| `teleportAim`, then `teleportCommit` on release | right stick forward past 0.7 with Y dominant, held until below 0.3 | T held |
| `flightToggle` | right B | F |
| `vertical` (up positive) | right stick Y | Space (up), C (down) |
| `menu` | left button index 6, or right A | M |
| `select` (level and edge) | either trigger | left mouse button, under pointer lock |
| `grip` (level and edge) | either grip | right mouse button, under pointer lock |
| `hands.left`, `hands.right`: `{ trigger, grip, stick }` (buttons level and edge, stick after the deadzone, x right, y forward) | that hand's trigger, grip and stick | none |
| `recenter`, once per 1 s hold | both stick clicks | R |
| Return to gallery (inside a world) | the panel's button | G |
| `abCycle` (edge), the A/B button | a single left stick click, on release | V, once per press |

- xr-standard has no menu slot. Index 6 is the thumbrest in IWER's Quest profile, so `menu` reads only `pressed` there. Whether Quest exposes its left menu button to WebXR is unverified, so right A also opens the settings panel (P5.3). A and Y are otherwise read only by the bench, which never builds the panel, so A is free wherever the panel exists.
- Left X (HUD), left Y (the bench's frame-rate step), right A (the bench's foveation step) and H (HUD) keep their own handlers outside the frame. Right A also feeds `menu`.
- `input.claim(left, right)` takes a hand out of `select` and `grip` for the rest of the frame. main.ts calls it right after the settings panel's frame with the hands the panel holds, so a trigger or grip on the panel never also selects, grabs or recenters. `input.holdSticks(left, right)` follows it with the hands grabbing the panel: that hand's stick stops feeding `move` (left) or `turn`, `vertical` and the teleport aim (right), a stick aim already held is dropped without a commit, and the stick stays out until it returns inside the deadzone, so letting go mid-push starts nothing. `hands` keeps the raw per-hand state.
- Dominant axis: a right-stick snap needs |x| > |y| and an aim needs y > |x|, so a 45° push does neither.
- Desktop deviates from the plan's map: C moves down instead of Ctrl, because Ctrl+W closes the tab. While the canvas holds pointer lock, Space and the movement keys (WASD, Q, E, C) have their browser defaults cancelled. The Enter VR button blurs itself after a click, so Space cannot press it again. The click that requests pointer lock never selects, so desktop select and grip work only under lock.
- `input.suppressHeld()` is for mode switches. Every held button (controller buttons, F, M, R, V and the mouse buttons) and a held teleport aim (stick or T) report nothing until released once. The continuous axes are not suppressed, and neither are the keys that mirror them (WASD, Q/E, Space/C).
- The recenter hold starts on the second held frame, because the first frame's dt predates the press.
- `abCycle` fires on the left stick click's release, and not at all if the right stick was pressed at any point during the hold, since both sticks held is recenter (`stickClickStep`). A left pad that vanishes mid-click (session end, tracking loss) cancels it too. It does nothing with no A/B group active. A held V does not repeat. `suppressHeld()` covers V and cancels a held click. Nothing else uses the single left stick click or V.
- With `?diag`, `__goghDiag().input` is `{ selectstart, actions }`, where `actions` is a copy of the last frame, or null before the first.

### Locomotion (P3.2 to P3.5)

- The camera sits in a rig, a three.js `Group` in the scene that carries the position and the rig yaw. XR's local-floor head pose and the desktop look stay inside it, so physical walking still works. `src/locomotion/step.ts` is the pure core and `src/locomotion/locomotion.ts` the wiring. XR and desktop share it. The bench never runs it, so its rig stays at the origin.
- Smooth movement: 2.0 m/s at full stick (`LocomotionSettings.moveSpeed`, clamped to 1.0-3.0) along the head yaw projected onto the ground, rig yaw included. Shift doubles it, capped at 3.0 m/s.
- Ground follow: the rig's y eases toward `WorldHandle.ground.heightAt` of the head's world XZ with an 80 ms time constant. With no world the floor is flat y = 0. While a world is loading the rig's y holds (not grounded) until its ground binds, so a spawn above y = 0 does not sink during the build. The desktop eye is 1.6 m above the rig.
- Seated mode adds its offset to the rig's y only, so physical head movement maps one to one into the world.
- Turning (`src/locomotion/turn.ts`, P3.3) rotates the rig yaw about the head's world XZ, not the rig origin, and re-solves the rig position so the head stays put. In XR the head is three's XR camera inside the rig, and on the desktop it is the eye, directly over the rig origin. Right is negative yaw. Snap mode (default) turns `snapAngleDeg` (30 or 45, default 30) once per `turn.snap`, at most once per 250 ms, and a request inside the cooldown is dropped. Smooth mode turns at `smoothTurnDegPerSec` (default 90, clamped to 30-180) times `turn.x`, and ignores `turn.snap`. The desktop Q and E keys feed the same `turn` action, so they snap too.
- The tunnel vignette (`src/ui/vignette.ts`, alpha in `src/ui/vignette-alpha.ts`, P3.3) is a black inside-out sphere of radius 1 m parented to the camera, with no depth test or write and `renderOrder` 999,000, below the perf HUD. It is a mesh, not post-processing, so fixed foveation stays intact. The fragment shader darkens by the angle off each eye's own forward axis: clear within 30°, ramping to full alpha at 50°. The ring is therefore centred on each eye's optical axis and carries no stereo disparity. On a real Quest the per-eye frusta are asymmetric, so it sits off the viewport centre there. `main.ts` compiles its program at boot with `renderer.compile`, so three links no new program on the first smooth move in XR. Whether the Quest driver still defers work to the first real draw is unverified.
- Its alpha is `LocomotionSettings.vignette` (default 0.6, clamped to 0-1) times the comfort factor: the larger of the smooth-move speed over the set `moveSpeed` and the smooth-turn rate over `smoothTurnDegPerSec`, capped at 1. Full stick, moving or smooth-turning, therefore reaches the full 0.6 strength at any speed setting, and half stick reaches 0.3. Snap turns add nothing. It eases with a 0.12 s time constant and lands on exactly 0 at rest, where the mesh is hidden and costs no draw call. It shows only while an XR session presents, so the desktop preview and its captures never draw it.
- Teleport (P3.4): `src/locomotion/teleport.ts` is the pure core. While `teleportAim` is held in walk mode, each frame traces a ballistic arc: 8 m/s along the aim ray, g = 9.8, 40 samples evenly spaced in time out to 15 m horizontally (or 3 s), with the landing bisected between the last sample above the ground and the first below it, then snapped onto `heightAt`. A landed arc is then resampled to 40 points evenly over its flight to the hit, so a short or steep-down arc still draws as a curve. In XR the aim ray is the right controller's target ray. `src/xr/right-controller.ts` creates both `renderer.xr.getController` slots at boot, parents them under the rig and picks the one whose input source has `handedness` `right`. On the desktop it is the camera's view ray from the eye. There is no aim while a world loads or while the right controller is untracked.
- A landing is rejected, in this order, where `boundaryFactor` is above 0 (from 45 m out, so nothing lands in the haze), where `WorldHandle.blocked(x, z)` is true, where `WorldHandle.treeBlocked(x, z)` is true, or where the ground normal is 45° or more from +Y (`MAX_SLOPE_DEG`). The limit was 35° until the headset pass showed it rejecting the painter's hill: its flank measures 35° to 41° at the default seed (triangle normals, 41.3° at most, and a 1 m central-difference average gives the same peak, so averaging does not help), and ground follow walks any slope. Other seeds reach 48°, so `?seed=8` still has ground that is rejected. Its reason is then `boundary`, `footprint`, `tree` or `slope`. An arc with no landing within 15 m has reason `none`. With no world the ground is flat y = 0, with no boundary, footprints, buildings or trees.
- Buildings cut the arc (`WorldHandle.volumes`, `src/paintings/starry-night/footprints.ts`). Each segment between consecutive samples, and the last one to the landing, is tested against every building's volume: its wall polygon grown by the 0.3 m margin, up to its top. The segment is clipped to the grown polygon, and the top is compared over the clip at its ends and where the gable bends, so a step cannot skip a corner or a ridge (the segment is a chord of the parabola and sags under 1 cm). A house's top is its gable: the eave over the long walls, rising to the ridge over the centre line. In the margin beside the long walls the top is the eave, and at the gable ends it stays on the gable profile. The church is two volumes, the tower to the spire's tip and the nave as a gable (eave `CHURCH_NAVE_EAVE` in `src/world/village.ts`, ridge along world z). The first segment that touches a volume ends the arc: the entry is found by halving the segment 16 times on the parabola, the hit is the point at the entry, the arc is resampled to 40 points up to it and drawn in the invalid colour, and the reason is `building`. So `aim.hit` is on the wall or roof, not on the ground, and no ring is drawn. An arc that clears the roof lands as usual. The origin is classified once per trace against each volume. A volume whose bare walls (the ungrown footprint, at or below the volume's top there: the gable, or the spire for the tower) hold the origin is ignored until a sample leaves those walls. A volume that holds the origin only in its 0.3 m margin is tested against its bare walls, with no margin, for the rest of the trace. So an aim from beside a wall is cut at the real wall and an aim away from it is free, and a player inside a house, or in the strip where the church's tower and nave margins overlap, can still teleport out. A volume left by the arc is tested against its bare walls too. A graze within 1 cm of a roof can report the hit up to one sample step past the wall. `footprint` remains for a landing in the margin of a world that has no `volumes`, and for the gallery. No mesh is raycast.
- The church footprint is its tower and its nave, two rectangles (`ChurchRecord.walls`), not their bounding box, so the open ground beside the tower is landable. The nave's 0.25 m roof overhang lies inside the 0.3 m margin, and a unit test walks the overhang outline. The tower has no overhang.
- Tree crowns reject landings and do not cut arcs: foliage is soft, and an arc through a crown ends on the far side as usual. `WorldHandle.treeBlocked(x, z)` (`createCrownTest`) is true when the landing's foot or its eye (1.6 m up) is inside the cypress or within the 0.3 m margin of it. It tests the crown's actual rings from the foot up to the eye, so a crown's lobes and its taper are followed, not a bounding disc. Both flame masses count, the main tree and the lower one. It is separate from `blocked` on purpose: the audio rustle reads `blocked` as walls.
- On `teleportCommit` after a valid aim, the rig moves so the head's world XZ lands on the hit, and its y goes straight to the ground (plus the seated offset) with no 80 ms ease. An invalid aim does nothing. In XR the move happens under a blink: the vignette's `setFade` takes the view to black over 90 ms, the jump happens on that frame, and the view fades back over 90 ms. On the desktop the jump is instant. A spawn or `__goghPose` cancels a blink in progress and clears the last trace. An aim still held then traces again from the new pose on the next frame.
- While aiming, snap and smooth turns are ignored, Q and E included. Smooth movement still works. Teleport is gated at one point in `locomotion.ts`: walk mode with no exit drop running. Flight and the drop both switch off the aim and the commit.
- The arc (`src/locomotion/arc-mesh.ts`) is its own instanced mesh on the stroke material and brush atlas. It draws one ribbon stroke per arc segment, starting 0.25 m from the origin so it stays clear of the 0.1 m near plane, each turned to face the eye. It is warm yellow #f2c84b when valid and red-grey #8c706c otherwise, with a ring of 10 strokes of radius 0.35 m on the ground at a valid landing. The ring is translated toward the head along the hit-to-eye line by 10% of the eye distance, clamped to 0.3-0.6 m and at most a quarter of the distance, recomputed each frame (`ringPull`). It stays on the same eye ray through its centre but draws slightly larger and floats a little above the ground, with the arc ending just beyond its centre, so it stays on top of the ground strokes. A house or terrain crest nearer the eye than the pull still hides it. Hidden, it is `visible = false` and costs no draw. Shown, it is one draw per view, so two in XR without multiview. It is built on the first stroke batch's atlas, so in a stroke scene (`?painting`, `?strokesTest`, `?demo=canvas`) it shares the batch's program, and an aim before the batch loads draws no arc. The bare scene has no batch, so it builds its own 2048² atlas and the arc on the first aim. A boot that never aims pays nothing for them, and the first aim pays the atlas build, its upload and the program compile.
- Flight (P3.5): `src/locomotion/flight.ts` is the pure core, and it replaces `step.ts` for the frame while the rig flies. `flightToggle` (right B, desktop F) toggles it. The toggle takes effect from the next frame, and it is ignored while a world loads or a teleport blink runs. Entering flight hides any aim and turns ground follow off.
  - The left stick moves at `moveSpeed` (Shift sprints, capped at 3.0 m/s) along the head's full 3D forward, pitch included, so looking up and pushing forward climbs. Strafing stays level. `vertical` (right stick Y, desktop Space and C) adds 2.0 m/s straight up or down. Turning works as in walk mode.
  - Altitude is the head's height above the ground under the head's world XZ. Over the last 5 m below 40 m the upward speed scales by the share of that band left, and the rig's y is then hard-clamped so the altitude never exceeds 40 m. The clamp takes the head's height as at least its expected eye height (1.6 m, less the seated offset when seated), so a pose-less first XR frame (head y 0) cannot leave the first real pose above 40 m. The floor is on the rig: the ground plus the seated offset, where walk mode stands it, so a standing eye never sinks below 1.6 m over the terrain.
  - The boundary push reads the world's `boundaryFactor` at the head's XZ with y = 0, so only the horizontal radius from the origin counts. Starry Night's factor also rises with altitude, which the cap already handles. Above factor 0.8 an inward velocity grows linearly to 3 m/s at factor 1, so full stick stalls short of 50 m and an idle flight drifts back to factor 0.8. The vignette's comfort factor takes the larger of the stick speed and the push speed, so push drift shows it too. The head's horizontal radius is then hard-clamped at 55 m. Both apply only with a world boundary, so the bare scene has neither. Walk mode has no radius clamp and is unchanged.
  - The haze thickens with the same factor while flying: 0 at 0.8 rising to 1 at 1, eased with a 0.25 s time constant, landing on exactly 0 in walk mode. `WorldHandle.setHaze` sets `uHazeThickness` on every band material, and the vertex shader grows each haze stroke by up to 50% (`HAZE_GROWTH`). The haze is the sky layer's only strokes with `SKY_LIGHT_CULL_FLAG`, because the flags byte has no spare bit. A chunk holding haze always culls with its half-diagonal widened by the full growth, so a thickened stroke never reaches past its cull sphere.
  - Leaving flight starts the exit drop: the rig's y follows a smoothstep from its flight height to the ground (plus the seated offset) under the head, re-sampled every frame, and lands on it exactly 0.5 s later. Ground follow then resumes. Smooth movement works during the drop. Re-entering flight cancels it at the current height, and a spawn or `__goghPose` returns the rig to walk mode. A teleport aim held across a flight toggle (T or the stick) counts for nothing until it is released, so holding it through leaving flight neither draws the arc nor jumps.
- With `?diag` outside `?bench`, `__goghDiag().rig` is `{ position: [x, y, z], yaw, mode, altitude, haze, seated, grounded, speed, turnMode, vignette, aim, lastTeleport }`, where `mode` is `'walk'` or `'fly'`, `altitude` the head's height above the ground under it in metres, `haze` the haze thickening (0-1), and `vignette` the last frame's alpha. `aim` is the last frame's `{ active, valid, reason, hit }`, with `reason` one of `ok`, `slope`, `boundary`, `footprint`, `building`, `tree` and `none`, and `hit` the landing [x, y, z] or null (for `building`, the cut point on the building). `lastTeleport` is null until the first jump, then `{ from, to, t }`: `from` is the head's world XZ at the rig's ground y before the jump, `to` the landing, and `t` the `performance.now()` ms of the move, after the blink in XR. `yaw` is the rig's own yaw only, not the view's: on the desktop the mouse look does not change it, but Q and E do, and in XR it excludes the head yaw. `grounded` is false while a placed pose or a loading world holds the rig, in flight and during the exit drop, and `speed` is the stick speed in m/s, vertical flight included.

## Settings (P5.2)

`src/settings/schema.ts`. One `localStorage` key, `gogh-xr.settings.v1`, holds `{ version: 3, settings }`. Version 3 changed the `qualityLevel` default from `'auto'` to 5, and its migration turns a stored `'auto'` into 5 once. The last position is never stored (PRD D12). `loadSettings()` returns `{ settings, recovered }`, and `saveSettings(settings)` writes. At runtime only the settings store writes it (below), and P5.6 will turn `recovered` into a notice.

- Fields and ranges: `moveSpeed` 1-3 m/s, `turnMode` snap|smooth, `snapAngleDeg` 30|45, `vignette` 0-1, `seated`, `standingHeight` 1-2.2 m, `calm` 0-1, `quality` `adaptive-72` (default: a 72 Hz target, with the adaptive governor only under `qualityLevel` `'auto'`)|`adaptive-90` (the governor at 90 Hz, with its 72 Hz fallback)|`beauty-72` (72 Hz with the max-beauty budget), `qualityLevel` an integer 0-18 (default 5) or `'auto'`, `hud`, `musicVolume` and `sfxVolume` 0-1 (the audio mixer's music and SFX buses, P6.5). The locomotion and calm ranges are imported from `src/locomotion/settings.ts` and `src/motion/clock.ts`.
- Out-of-range values are clamped and wrong-typed or missing fields take their default. Old versions migrate through `MIGRATIONS` (a step per version). v1 to v2 turns a stored `adaptive-90` into `adaptive-72`, since v1 saved the whole object on any change and its `adaptive-90` was almost always the old default. v2 to v3 turns a stored `qualityLevel` `'auto'` into 5 for the same reason. The migrated settings are written back only when a setting next changes.
- `recovered` is null, or `corrupt-json`, `bad-shape`, `future-version` or `storage-unavailable`, and the settings are then the defaults. A first run with nothing stored is not a recovery. The boot logs it as a warning.
- URL flags win for the session (`applyUrlFlags`): `?beauty` selects `beauty-72`, `?hz=72` selects `adaptive-72`, and `?hz=90` or `?hz=120` selects `adaptive-90` over any stored quality, `?turn` sets the turn mode, `?calm` sets calm, `?seated` and `?hud` turn their field on, and `?seated=0` and `?hud=0` (or `=false`) turn it off over a stored on. The stored object is untouched. `lockedSettings(flags)` maps each field a flag overrides to the flag as written (`?beauty`, `?hz=90`, `?seated=0`, `?turn=smooth`, `?hud`, `?calm=0.5`), and both panels show those fields locked, with help text naming the flag.
- The settings store (`src/settings/store.ts`, P5.3) is the one live copy, created at boot from the loaded settings and the flags. `set(key, value)` refuses a locked or unchanged value, clamps it, recomputes the effective settings, notifies subscribers at once and schedules the save `SAVE_DELAY_MS` (500 ms) after the last change. `commit()` saves at once: the panels call it when a slider is released and on each toggle or segment press. A locked field is never written back, so the stored value keeps whatever was saved before the flag.
- Live apply: main.ts subscribes `applySettingsChange` (`src/settings/apply.ts`) to the store. It hands every change to locomotion (`setSettings`, so move speed, turn mode, snap angle, the vignette, seated and standing height act on the next frame, and a change to seated or standing height recaptures the seated offset), calm to `motionClock.setCalm`, and a `hud` change to the HUD's visibility when it differs from what shows.
- `qualityLevel` is a fixed governor level (default 5) or `'auto'` (the adaptive governor), rounded and clamped to 0-`MAX_QUALITY_LEVEL` (18, beauty's ladder). It is a constant in `schema.ts`, so the boot chunk builds no governor, and `tests/governor-fixed.test.ts` checks it against the ladders. The default is a fixed level 5 (Paul, 2026-11-09: quality over frame rate), because on Auto the governor keeps adjusting and the strokes jump. Level 5 is in range for both ladders (`5 · far 0.20` in the default modes, `5 · far 0.39` in beauty). A non-numeric value means 5. A level past the session mode's ladder (17 or 18 outside beauty) applies the whole ladder. Settings version 3 carries the change: the store saves the whole object on any change, so it cannot tell a stored default from a choice, and the v2-to-v3 migration turns a stored `'auto'` into 5 once. An `'auto'` chosen at v3 or later is kept, and a stored object without the field sanitizes to 5. It applies live, on the next frame (see the governor's fixed level under URL flags). `?nogov` locks it (`lockedSettings`).
- Quality applies at the next XR entry, not live: the session's requested frame rate and the governor's mode and budget read the effective quality at `sessionstart` (the governor's `reset()` re-reads `deps.mode` and `deps.targetHz`). While a session runs on another quality, the panel's quality row reads "applies on next entry".
- `musicVolume` and `sfxVolume` are live sliders on both panels, in 0.05 steps: a change reaches the audio buses at once (main.ts calls `audio.setVolumes` from the store subscription) and is saved like any other setting.
- With `?diag`, `__goghDiag().settings` is `{ stored, effective, recovered, saves, pending }`, where `saves` counts the writes this page made and `pending` is true while a debounced save waits.

### Settings panel (P5.3)

- One panel per mode, each built lazily on its first open (`src/ui/panel-toggle.ts`), so a session that never opens one loads neither and the XR panel costs no draw. There is no panel in the bench. `menu` toggles the XR panel while presenting. M toggles the DOM panel on the desktop, once per physical press (on keydown, auto-repeat ignored). XR entry closes the DOM panel, and XR exit saves the XR panel's pose and closes it.
- The XR panel (`src/ui/settings-panel.ts`, layout in `src/ui/panel-layout.ts`, pure ray and grab maths in `src/ui/panel-core.ts`) is a 0.62 × 0.58 m rig child: a near-black blue backing, every border, fill, slider track and knob as one instanced stroke mesh on the stroke material and the shared atlas (the bound batch's, or the bare scene's own, shared with the arc), all labels in one troika `BatchedText` (Noto Sans), the two lasers as one line mesh, and the contact markers as one instanced ring mesh. In a stroke scene the panel's strokes reuse the batch's program: tests/e2e/panel.spec.ts checks that a first open adds 4 programs there and 5 in the bare scene. Open, it adds up to 5 draws per view (14 against 4 closed in IWER's two views, with a laser on a control), and the markers draw only while a laser hits. The hover help adds 1 more per view while shown (16), since its text is a member of the same batch. Closed, it draws nothing (4 again). While a slider drags, its label changes reach troika at most once per 100 ms (`src/ui/text-throttle.ts`), since each change re-typesets on the next render. Otherwise they land on the frame they change. Its controls are one per setting: move speed, turn mode, snap step, comfort vignette, seated, standing height, painting motion (calm), quality (three segments: "72 Hz", "90 Hz" and "Beauty"), quality level, performance HUD, the music and sound-effects volume sliders, Recenter and Return to gallery.
- Each controller's laser reaches 3 m and stops at the nearest hit, with a ring marker at the contact. Controls are hit only from the front, 4 mm proud of the backing, and the backing is hit from both sides. Hover help appears beside the panel after 700 ms on one control, and hides while a hand grabs or presses.
- The trigger operates controls: a toggle or segment on press, a slider from press until release, even if the laser leaves the panel. Grip on the panel grabs it and never activates a control, and a grip during a press cancels the press. One hand carries the panel rigidly with the controller's pose, and its stick adjusts the hold per the webxr guide's controller contract, at 90°/s or 1 m/s at full stick: grip + stick X yaws the panel about its own Y (right positive), grip + stick Y pitches it about its own X (stick back, raw gamepad +Y, positive), grip + trigger + stick Y pushes it along the laser (forward away), kept 0.15-2.5 m along the laser from the controller, and grip + trigger + stick X rolls it about the laser (right positive about the forward axis). The trigger held with a grip operates nothing, and a single hand never changes the scale. Two hands ignore the sticks and scale it by their spread, clamped to 0.5-1.8, rotate it with the line between them and move it with their midpoint. Releasing one hand hands over to the other without a jump. A hand the panel holds (a trigger press that started on the panel, until its release, or a grab) is claimed out of `select` and `grip` for the frame, and recenter waits while either is held.
- Its pose saves under `gogh-xr.panel.v1` relative to the head's yaw (position offset and orientation in the head-yaw frame, plus scale) on each grab release, on a close mid-grab and on XR exit, and an open restores it against the current head. A save clamps the offset's length into 0.25-2.5 m along its own direction, so a panel pushed further away still restores. With nothing saved, or a stored pose that fails validation (non-finite numbers, a distance outside 0.25-2.5 m), it spawns 0.72 m ahead and 0.16 m below the eye, facing the head.
- Recenter (both stick clicks held 1 s, R, or the panel's button) turns the view to the world's spawn yaw about the head (`locomotion.faceYaw`, which counts a discontinuity), clears the saved panel pose and respawns an open panel in front of the head at scale 1. It calls `input.suppressHeld()`, so the trigger that pressed the panel's button reaches nothing else until it is released.
- Return to gallery calls the callback that `registerGalleryReturn(cb)` registers. main.ts registers one when a painting's world binds and clears it in the gallery. With none registered, both panels hide the button, and a hidden control takes no hits. The panel works the same in the gallery, the default boot. tests/e2e/panel.spec.ts operates it there, and checks that a press where the hidden button sits leaves it open.
- tests/e2e/journey.spec.ts (P5.7, P5-A2) walks the whole path with real input, under IWER and on the desktop: from the gallery spawn into Starry Night (left stick or W), the panel (left button index 6 or M), the vignette (laser and trigger, or a mouse click on the DOM slider), Return to gallery (the panel's button), then a reload that must keep the vignette. It asserts state only, so it is in the `e2e` project. Specs share diag readers and the panel aiming helpers through `tests/e2e/helpers.ts`.
- Quality level is a slider in the World column, row 5 (default 5): Auto at the left, then 0 to the governor mode's ladder length (16, or 18 for beauty), in steps of 1. The mode is the running governor's own (`strokes.governorMode()`), and with none running the one the quality setting starts (`ladderMode`), so the row and the governor never disagree, even after the governor re-reads a changed quality at a session end or a world bind. The value reads "Auto", "0 · full", or the level and the step it adds, such as "3 · fov 1" or "7 · far 0.10", and each level keeps every step below it. The help says so and spells out the order. The DOM row's title adds every lever the selected level sets (`qualityLevelSummary`, such as "fov 1, fb 0.85, far 0.10"), and its range input's `aria-valuetext` is the value text. Auto is -1 on the track (`AUTO_SLIDER`), mapped by `sliderSetting` and `settingFromSlider` in `panel-layout.ts`, and the track's max follows the mode (`liveSliderDef`). A slider value at the place the stored level already shows keeps it, so a stored beauty 18, shown at 16 on the adaptive ladder, survives a press that moves nothing. tests/e2e/settings.spec.ts sets it with the keyboard on the DOM slider, checks `__goghDiag().governor.fixedLevel` and the levels, reloads, and sets Auto again.
- The DOM panel (`src/ui/settings-dom.ts`, `section#gogh-settings`) mirrors the same controls, store and buttons, with `data-control` attributes. Opening it releases pointer lock, and taking pointer lock closes it. Locked rows are disabled, with the flag in their `title`.
- With `?diag` outside `?bench`, `__goghDiag().panel` is `{ built, open, surface, domBuilt, pose, scale, hover, tooltip, grabbing, typeset, locked }`: `built` is the XR panel, `surface` is `'xr'`, `'dom'` or null, `pose` (`{ position, quaternion }`, rig-local), `scale` and `hover` (`{ left, right }` control ids) are null unless the XR panel is open, and `locked` is the `lockedSettings` map.

## Gallery (P5.4)

`src/paintings/gallery/`. The default boot: with no `?bench`, live `?painting`, `?strokesTest`, `?demo` or `?scene=bare`, the app builds the gallery, a world module behind the same `WorldHandle` contract as Starry Night. `resolveBootMode` (`src/boot-mode.ts`) holds the precedence: `?bench` (with a value), then `?painting` (a live id builds its world, and an unknown or coming-soon id warns and is ignored, falling through to the flags below), then `?strokesTest` or `?demo=canvas`, then `?scene=bare`, then the gallery. `tests/boot-mode.test.ts` pins it.

- The room (`layout.ts`) is 6 m (x -3 to 3) by 10 m (z -4 to 6) with a 3.5 m ceiling. Starry Night hangs alone on the north wall (z = -4). In registry order, chestnut and Alyscamps hang on the east wall, Café Terrace and Bedroom on the south wall, and Wheatfield and Rhône on the west wall. Every frame is centred at 1.6 m at its painting's true size (`widthCm` × `heightCm`), with a 7 cm moulding. `tests/gallery-layout.test.ts` checks no frame or plaque overlaps on a wall, each lies inside its wall, and each matches its painting's aspect.
- The scans are images: each `frame.webp` on a plane, sRGB, mipmapped, anisotropy min(8, the renderer's max), `toneMapped` false, with a -2400 unit polygon offset so the stroke depth tie-break never lifts a wall stroke over it. `coverCrop` crops each scan by UV to its painting's aspect. The chestnut scan loses 6.4% of its height, 70% of that from the bottom (`CROP_BIAS`). The rest lose under 2.5%.
- The walls, floor, ceiling, benches and mouldings are strokes (`surfaces.ts`) over one flat vertex-coloured base mesh, about 147k strokes in all, all depth-ranked. The palette (`palette.ts`) is sampled from the scans and muted, and `tests/gallery-palette.test.ts` re-derives every sample from the files. There are no lights: each stroke carries a light factor, a wash on the wall around each frame, darker corners and wall tops, a faint pool on the floor in front of each frame, and bench tops lit above their sides. Each frame's wash is capped by its own scan's median luma (`SCAN_MEDIAN_LUMA`, `wallGlow`), so the wall within 0.3 m of a frame averages at most 0.85 of that median and its brightest strokes stay under it, which `tests/gallery-surfaces.test.ts` checks against every scan.
- The mouldings stand 5 cm off the wall, and from far enough away the stroke depth tie-break could pull a wall stroke over them. A wall stroke whose quad can reach a moulding therefore takes a tie-break share under `NEAR_FRAME_SHARE` (0.3): the scatter nudges its size by a few ulps until `sizeShare` falls under it. That keeps it behind the moulding from anywhere in the room.
- The plaques (`plaques.ts`) are troika text from the local NotoSans-Regular: the title at 30 mm per em and the year, museum and "Coming soon" at 21 mm, on a dark card beside each frame, centred at 1.3 m. The title and the details read as one block, the details a fixed gap under the title's typeset bottom, centred on the card, and each card has a thin moulding-gold edge. They typeset after the build, off its critical path, and never under `?bare`. The seven cards and their edges are one merged, vertex-coloured mesh (one draw call) and each plaque two text meshes, so a plaque in view costs two draws. The text uses troika's `depthOffset`, which overwrites its material's polygon offset, to sit over the card.
- `WorldHandle`: `ground` is flat y = 0, `boundaryFactor` is 0 inside the room and 1 outside, and `blocked(x, z)` is true within 0.3 m of a wall or a bench. `spawnPose()` and the painter spot are (0, 0, 0) facing -Z, 4 m from Starry Night. `painterCamera()` is the eye (0, 1.6, 0) facing -Z, vertical FOV 46°, aspect 16:9.
- `walkBounds` (`src/locomotion/walk-bounds.ts`) is an optional `WorldHandle` field: a box `{ minX, maxX, minZ, maxZ, maxY }` the head must stay in. After each frame's step or flight, `clampToWalkBounds` translates the rig so the head's world XZ lies in the box and the head's y stays under `maxY`. A placed pose (`__goghPose`, `?painter`) is left where it was put until the next movement. The gallery's box is the room minus 0.3 m and a 3.2 m ceiling. Starry Night sets none, so it is never clamped. `opening: { side, from, to }` lets the head through one side while its other coordinate is in [from, to]: the seam for P5.5's Starry Night portal.
- With `?diag`, `__goghDiag().world` is `{ painting: 'gallery', seed, debug, counts, total, times, cache: 'bypass', strokes, frames, plaques }`. `counts` is per role (`wall`, `floor`, `ceiling`, `bench`, `moulding`). `times` is `{ decodeMs, generateMs, scatterMs, batchMs, buildMs }`, where `decodeMs` is the wait for the scans after the batch and the atlas is excluded. `frames` is one `{ id, loaded, naturalWidth, naturalHeight, keep: [u, v] }` per scan. `plaques` is `{ state: 'pending' | 'built' | 'failed' | 'skipped', ms, drawCallsPerPlaque, lines, texts }`.
- Under `?bare` the scans turn magenta and the plaques are skipped. Under `?coverage` the scans and plaques draw normally. `tests/e2e/gallery.spec.ts` holds four poses (spawn, the Starry Night wall, the east wall, the back wall) to 0.5% bare. `GALLERY_SHOTS=1` makes it write `docs/shots/p54-gallery-{wide,starry,west}.jpg` and `p54-plaque.jpg`. `GALLERY_MOULDING=<label>` runs the far moulding probe: from (2.4, 1.6, -3.6) facing the south wall and (0, 1.6, 5.7) facing Starry Night, at 3200 × 1800 (about Quest density), it counts slate pixels in the gold bars and their flicker over 8 sub-millimetre eye jitters, and writes 3× crops to `docs/shots/p54-moulding-<label>-<id>.png`.

## Notices (P5.6)

- One queue (`src/ui/notice-queue.ts`, pure), newest first and deduped by kind: a notice of a kind already queued replaces the older one and moves to the front. At most 2 show at once (`MAX_SHOWN`). `src/ui/notices.ts` is the host, and both surfaces draw the queue's `shown`, so a dismissal on either removes the notice from both.
- Kinds and where they are raised, all in `main.ts`:
  - `rate-fallback`: the governor's `notify` (72 Hz fallback), routed by `raiseRateFallback` in `src/ui/notices.ts`. It no longer shows the perf HUD, and the HUD carries no notice line (R16, superseded by Paul on 2026-11-08). The XR stack does not depend on the perf HUD: tests/e2e/governor.spec.ts checks the notice on the stack with the HUD hidden and unbuilt, and tests/notices.test.ts pins it.
  - `settings-recovered`: at boot, when `loadSettings` reports any recovery reason, `storage-unavailable` included. Texts are in `settingsRecoveredText`.
  - `xr-error`: the session controller's `notify`. A successful XR entry dismisses only this kind, so a settings or rate notice carries into XR.
  - `world-failed`: a world that failed to load. The portal switcher's `loadFailed` dep (wired in `main.ts`) raises it when a transition's target fails to build, whether by a throw, the 12 s import timeout or the 30 s raster timeout (`worldFailedText(name)`: "The Starry Night could not load. Try again, or reload the page."), or because the stall watchdog gave up (`worldFailedText(name, 'stall')`: "... took too long to load. ..."), before the gallery fallback runs. A `?painting` boot raises it too (see `?painting`). A retry refused while a given-up build is still in flight raises it too, as "... is still loading. Try again in a moment." (`worldFailedText(name, 'loading')`). It clears itself when a transition reaches its target with no fallback (`SwitcherDeps.entered`); the gallery fallback after a failure does not clear it. A successful `?painting` boot has nothing to clear. Without notices it falls back to the plain DOM notice. Dismiss only, no action.
  - `update-ready`: the build poller (P7.1, see Updates below), through `notices.raiseUpdate()`. A rollback dismisses it. It is the one kind with an action: a Reload button left of Dismiss on both surfaces (`NoticesDeps.actions`). Pressing Reload runs the action and leaves the notice up.
- On the 2D page the notices are DOM notices (`src/ui/notice.ts`, `data-notice-kind`), with a Dismiss button, and the update notice's Reload button (`data-notice-action="reload"`) before it. They are invisible in immersive mode.
- In XR they show on the notice stack (`src/ui/notice-hud.ts`): troika text on small plates parented to the camera, 0.6 m out, with the bottom edge 13° above the eye line, clear of the perf HUD below and of the panel's default spawn. The newest is at the bottom. When an open panel would sit behind the stack, it lifts to 2° above the panel's top edge if that keeps its bottom edge within 40°, and otherwise drops so its top edge is 2° below the panel's bottom edge if its bottom edge stays above -8°, clear of the perf HUD. When neither fits it stays at 40° and may cover the panel, which still owns the trigger (`src/ui/notice-geometry.ts`). Elevation there is the pitch about X, `atan2(y, -z)`, which is constant along the stack's bottom edge. Placement has 2° of hysteresis (`PLACEMENT_BAND`, `NoticePlacementState` passed back into `noticeElevation`): a moved stack stays moved until the panel clears the overlap by the band, a lifted stack stays lifted until the lift passes 40° by the band (held at 40° meanwhile), and a dropped one stays dropped until the lift is within 40° by the band, so a panel held on a boundary never flips the stack. The applied elevation eases to the placement with a 0.15 s time constant (`ELEVATION_TAU`, `easeElevation`, frame-rate independent in the frame's `dt`). It snaps on the first frame the stack shows, on the frame the panel opens, whenever the placement switches between lift and drop (either way), when it goes into the cap from a drop or the base, and from the base to a lift (a held lift is clamped to max(eased, target) and a held drop to min(eased, target), `appliedElevation`, so the stack is never on the panel's side of its target). Every other placement change eases away from the panel: lift to base, drop to base, and lift to cap. `view.elevationDeg` in `?diag` is the applied (eased) value. It is built on the first presenting frame with a notice queued, so a boot that never shows one in XR loads none of it. While it shows and the panel is closed, a laser from each tracked controller shows the aim.
- Trigger rule (`arbitrateNoticeTrigger`): the settings panel owns a hand's trigger whenever that hand's ray meets the panel (backing or control) or the panel holds the hand, whatever notice lies on the same ray. A notice takes only a fresh press (`fired`) whose ray meets one of its own buttons (Dismiss, or the update notice's Reload) and not the panel. A ray's target is a `NoticeHit`, `{ kind, button: 'dismiss' | 'action' }`, the nearest button it meets. The press stays the notice's until released, so main.ts claims that hand and the hold never reaches `select`. If the panel claims a hand during a notice press (a grip on the panel), the panel has it from then on. Each hand is judged alone. `PanelHold` carries the panel's per-hand `hits` and its open `pose` for this.
- Notices hold no controls: every preference has one owner, the settings panel.
- The bench builds no notices and keeps the plain DOM notice for its XR errors.
- With `?diag`, `__goghDiag().notices` is `{ queue: [{ kind, text }], shown: [...], view }`. `view` is null until the stack is built, then `{ visible, elevationDeg, typeset, targets: [{ kind, center, hovered }], actions: [{ kind, label, center, hovered, visible }] }`. `targets` are the Dismiss buttons and `actions` the action buttons (Reload). `center` is the button's world centre, `hovered` means a hand may press it, and an action's `visible` is computed: the button and every ancestor up to the scene are visible. `window.__goghNotice(kind, text?)` raises a notice of `kind` straight into the queue, with `text` (default: the kind name, or `UPDATE_NOTICE` for `update-ready`). It does not show the perf HUD, and neither does the governor's 72 Hz path. `tests/e2e/notices.spec.ts` covers every kind.

## Updates (P7.1)

- The build id (`scripts/build-version.ts`, a Vite plugin for every build, dev server excluded) is a SHA-256 over the final bytes of every emitted chunk and asset except sourcemaps (its `generateBundle` runs with `order: 'post'`, after Vite's own last rewrite of the chunks), the package version and every file under `public/`. Two builds of the same tree give the same id. It is written into index.html as `<meta name="gogh-build-id">`, which the running page reads as its baseline (`src/update/policy.ts`), and into the same-origin `version.json` `{ buildId, version }`. The first poll is never the baseline. The scatter cache stays keyed on `__BUILD_SHA__`, not on the build id.
- In an e2e build only, `GOGH_BUILD_SHA` overrides `__BUILD_SHA__`. Only `scripts/update-ab.ts` sets it, to build two different bundles from one tree. A production build ignores it.
- The poller (`src/update/check.ts`) checks once at boot, then every 30 s. Each request has a 5 s timeout that covers the body, uses `cache: 'no-store'` plus a `t` query (Pages' CDN caches for 10 minutes), and never overlaps the previous one. A failed or malformed poll keeps the notice. Teardown (`pagehide`, unless the page goes into the back-forward cache) aborts the request in flight.
- Where it runs (`shouldPoll`): a production build polls unless `?update=0`. An e2e build (`--mode e2e`) polls only with `?update`, so no other spec sees a reload when the served build changes. The dev server never polls, because it has no build id or `version.json`, and `?update` cannot turn it on there. The bench never polls.
- On the desktop a new build reloads by itself, unless an XR session presents or the page is busy: an XR entry or a portal transition (`switcher.busy`) is under way. A busy page reloads once it is idle again, and a Reload selected while busy waits the same way. In XR it never reloads by itself: it raises `update-ready`, whose Reload ends the session, waits for its `end`, flushes the settings save (`settingsStore.commit()`, because saves are debounced 500 ms), and navigates (`src/update/updates.ts`). A session that does not end within 10 s keeps the page and raises `xr-error`. A build that arrives in XR, or during an entry, reloads once the viewer is back on the page.
- Loop guard: every reload records `{ from, at }` under `gogh-xr.update.lastReload` in sessionStorage. The page does not reload by itself again when it came back running the id it reloaded away from (an inconsistent deploy), or when the last reload was under 2 minutes ago. It shows the notice with its Reload instead, and `__goghDiag().update.guarded` is true. The 2-minute hold is retried once the window ends, because the poller reports a new build only once, and teardown clears that retry. The same-id hold lasts for the tab.
- The reload URL (`src/update/reload.ts`) keeps every query parameter byte for byte (`?hud` stays `?hud`) and the fragment, and appends `_reload=<ms>`, so a cached index.html cannot serve the old build. The new page removes `_reload` from the address bar at boot (`history.replaceState`).
- With `?diag` and a poller, `__goghDiag().update` is `{ running, available, reloading, guarded, checks }` and `window.__goghUpdateCheck()` polls at once.
- `make update-ab` (`bun scripts/update-ab.ts [--out dir]`) is the served A-to-B check (P7-A1). It builds e2e bundles A and B, serves A on `E2E_PORT` (default 4298) with `Cache-Control: max-age=600`, switches that origin to B, and checks the desktop auto-reload and the IWER Reload path. B is also served alone on `UPDATE_B_PORT` (default 4299). It waits up to 15 minutes for a 1-minute load of 15 or below before each mode, and writes `result.json` and screenshots.

## Audio (P6.4)

- Sources live in `assets/audio/source/` and are never written. `make audio` (`scripts/audio/master.ts`) masters them into `public/audio/` as `<id>.ogg` (Opus) and `<id>.mp3`, writes `public/audio/manifest.json`, and rewrites `docs/audio/derivatives.md`, which records every command, gain, measurement and hash. Its float WAV intermediates go to `build/audio/`, which is git-ignored. The per-cue values (trim, crossfade, limiter, bitrates, Ogg serial, budgets) are in `scripts/audio/contract.ts`.
- Music is 48 kHz stereo at -18 LUFS ±1, as a 120-180 s loop. The SFX beds (wind-hill, crickets) are 48 kHz mono at -24 LUFS ±2, the target the plan sets. The one-shots (church-bell, portal-whoosh, stroke-rustle) use the same -24 LUFS ±2 as a proposed target, pending Paul's confirmation. Every file has a true peak of at most -1 dBTP after encoding. Loops are wrapped tail-to-head: the loop starts after the consumed intro, and its last frame leads into its first.
- `make audio` stages into `build/audio/out/`, then promotes to `public/audio/` and deletes any file there that the build did not produce.
- `make asset-check` runs two audio steps after the provenance hashes:
  - `bun scripts/audio/validate.ts --self-test` first runs the fixtures. The baseline must pass, and each of 11 synthetic mutations must fail for exactly its own reason. Four more seam mutations, 15 in all, re-encode a committed loop with a click near the wrap (0.15, 0.2 and 0.3 on the last 3 samples of crickets, an impulse 5 ms before the score-night seam), and both formats must fail for `[wrap]`. It then recomputes every check from the current `public/audio/` files: source hash, the source's 0.5L + 0.5R fold for mono cues, manifest shape, files the manifest does not name, file hash and size, codec and format, decoded frame count, loudness, true peak, the seam, head and tail balance, interior gaps, and the mono fold. It also fails when the contract hash in `docs/audio/derivatives.md` no longer matches the text of `scripts/audio/{contract,master-lib,master,ffmpeg}.ts`. That hash detects a stale contract, not a loosened one, because the check logic in `validate-lib.ts` and `metrics.ts` is not hashed. Each failure prints as `[reason]`.
  - The seam check takes a ±6 ms window across the wrap and compares its largest sample step, full band and below 1 kHz, with the 99.9th percentile of the same statistic over the loop's own 12 ms windows. It fails above 1.5x (`LIMITS` in `contract.ts`). The limit is relative to the loop's own p99.9 step, so it has a detection floor: on a busy loop a small seam step hides inside the loop's own texture. Measured on the shipping files, full band and below 1 kHz: a +0.1 DC step on wind-hill reads 1.34x and 1.25x, and a +0.1 click on crickets reads 1.38x and 1.20x, and both pass. A +0.15 click on crickets reads 0.59x and 1.97x in Ogg and 0.57x and 1.75x in MP3, and fails for `[wrap]` (the `seam-click-0.15` fixture). Do not treat a green seam check as proof of a seamless wrap below about 0.15 of full scale.
  - `bun scripts/audio/master.ts --check` rebuilds into `build/audio/out/` and fails unless every file comes out byte-identical, or `public/audio/` holds a file the build did not produce.
- Pending owner deviations: a cue's `deviations` in `contract.ts` (`status: 'pending-owner'`) never fail the gate. Each prints a named `WARN` line on every run until Paul decides. `tests/audio-provenance.test.ts` fails when a cue's pending deviation here and its "Technical preparation" status in `docs/audio/provenance.md` disagree, in either direction, so resolving one means editing both. A `source-fold` deviation waives the source fold check only up to its `upToDb`. Current ones:
  - wind-hill (`crest-limited`): linear gain to the ceiling stops near -29.4 LUFS, so the shipping file is peak-limited to reach -24.
  - portal-whoosh (`source-fold`): the source loses 2.48 dB in the mono fold, against the 2 dB limit.
- `make audio-audition` renders the limited and the linear take of each `crest-limited` cue into `build/audio/audition/` (git-ignored, never committed), for Paul to compare.
- FFmpeg pin: 9.0.2 (libavcodec 63.1.102, Homebrew `ffmpeg-full`, with libopus 1.6.1 and LAME 4.0). `make audio` refuses any other build, and `master.ts --check` skips on one. The validator and its self-test warn and still run, because none of their checks needs byte identity. The validator fails if ffmpeg is not on PATH. `AUDIO_FFMPEG_SIMULATE_VERSION=<version>` is test-only: it replaces the detected version string, so `AUDIO_FFMPEG_SIMULATE_VERSION=8.0 make asset-check` exercises the degraded path on the pinned build. CI has no asset-check job, and the vitest fixture suite (`tests/audio-validate.test.ts`) skips unless the pinned ffmpeg is present, so CI runs only the pure metric tests.
- Never edit `public/audio/` or `docs/audio/derivatives.md` by hand. Change the contract and re-run `make audio`, or `--check` fails.

`public/audio/manifest.json` is the interface for the P6.5 mixer. File names are relative to the manifest's own directory:

```ts
interface Manifest {
  version: 1;
  sampleRate: 48000;
  ffmpeg: string; // the FFmpeg version that built the files
  cues: {
    id: string; // score-night, score-gallery, wind-hill, crickets, church-bell, portal-whoosh, stroke-rustle
    kind: 'music' | 'sfx';
    loop: boolean; // true for the two scores, wind-hill and crickets
    channels: 1 | 2; // music 2, SFX 1 (positional)
    duration: number; // seconds, frames / sampleRate
    frames: number; // every file decodes to exactly this many frames
    loudness: { target: number; tolerance: number }; // integrated LUFS and LU
    files: { ogg: string; mp3: string }; // Opus first, MP3 as the fallback
    bytes: { ogg: number; mp3: number };
    sha256: { ogg: string; mp3: string };
  }[];
}
```

## Audio (P6.5)

`src/audio/`: `mixer.ts` (the WebAudio graph), `audio.ts` (the host main.ts drives), `cues.ts` (cue ids and the manifest), `placement.ts` (the positional anchors) and `rustle.ts` (the rustle trigger). Unit tests run on a fake `AudioContext` (`tests/audio-fake.ts`).

- Unlock: no `AudioContext` exists until the first user gesture, the Enter VR button or a `pointerdown`, `pointerup`, `touchend` or `keydown` on the page (capture phase). The context is created on the first of these and resumed inside it, and the mixer is built on it at once. A touch or pen `pointerdown` carries no user activation, so its resume can stay pending: each later gesture asks a context still suspended to resume, and the listeners are removed once it runs. There is only ever one context. `?bench` creates no host, no listener and no context, which `tests/e2e/audio.spec.ts` checks by counting `AudioContext` constructions.
- Graph: score voices → per-voice gain → music bus, and SFX voices → gain → HRTF `PannerNode` (positional cues only) → SFX bus. Both buses feed one master gain, then the destination. The buses follow the `musicVolume` and `sfxVolume` settings live (`setTargetAtTime`, 30 ms), read at the unlock and on every store change. `?mute` (boolean) starts the master at 0. The buses keep their levels, and nothing else changes.
- Manifest: `public/audio/manifest.json` (P6.4) is fetched under Vite's base at the unlock. Its shape is `{ version: 1, sampleRate, ffmpeg, cues: [{ id, kind, loop, channels, duration, frames, loudness, files: { ogg, mp3 }, bytes, sha256 }] }`, and each file name resolves relative to the manifest (`<base>audio/<file>`). `parseManifest` reads only `version`, `id`, `kind`, `loop`, `channels`, `duration` and `files`: it rejects a manifest that is not version 1, and drops a cue whose id is unknown or repeated, whose kind does not match its id, or which has no safe file name (no `..`, no absolute path). `tests/fixtures/audio-manifest.json` is a verbatim copy of P6.4's manifest that the unit tests parse. Ogg Opus is used where `canPlayType('audio/ogg; codecs=opus')` is non-empty, else MP3, each falling back to the other file. A missing or malformed manifest logs one warning and the app runs silent, with no notice. A missing or undecodable file logs one warning for its cue, which stays silent. A response that is not OK, or is HTML, counts as missing, because Vite's dev and preview servers answer a missing path with index.html and a 200. On Pages a missing file is a real 404, which the browser logs as `Failed to load resource`, and the e2e `pageErrors` fixture ignores that message for `/audio/` paths.
- Scores: `score-gallery` in the gallery and `score-night` in Starry Night (`scoreFor`). Others play none. The first score fades in over 2 s (`SCORE_FADE_IN_S`). A world change crossfades at equal power over 3 s (`SCORE_CROSSFADE_S`, 16 linear segments of sin and cos), from the portal trigger, the first frame `switcher.busy` is true, so the build wait does not stretch it. When the target score still has to decode, the old score holds at its level until the decode finishes, then both fades start together. A reversal before then (a target set back to the score still at full) keeps that voice and starts nothing. The whoosh plays at the same moment, non-positional. `bindWorld` sets the score again, so a failed build's gallery fallback crossfades back from wherever the fade had got to. A score restarted while its own voice still fades out starts at that voice's place in the loop, so it comes back in phase. Only the playing score and a crossfade's target are decoded (a 150 s stereo score is about 58 MB of float32), and a score's PCM is dropped once its voice has faded out. Its compressed bytes are kept to decode it again. At most 3 score voices exist (`MAX_MUSIC_VOICES`): past that, the oldest fading one stops at once.
- Positional cues, Starry Night only (`ambienceFor`). The anchors are seed-1 generator output, re-derived from `createVillage` and `createCypress` by `tests/audio-placement.test.ts`. Other seeds move the steeple by up to about 2 m:

  | Cue | Position (world, m) | Panner (ref, rolloff, max) |
  | --- | --- | --- |
  | `church-bell` | (3.57, 2.2, -36.83), 3 m under the spire tip | 20, 1, 400 |
  | `wind-hill` | (-3.82, 2.10, -9.11), halfway up the main cypress | 6, 1, 200 |
  | `crickets` ×5 | xz (-12, -7), (10, -6), (-5, 9), (8, 11), (-16, 3), 0.15 m above the ground | 3, 1.2, 120 |
  | `stroke-rustle` | the hand that pushed | 0.5, 1, 20 |

  The beds (wind and crickets) loop from random offsets, fade in over 2 s when the world binds, and fade out over 1 s at the portal trigger. The bell rings first 10-30 s after the world binds and its beds start, then every 60-120 s (`BELL_FIRST_S`, `BELL_INTERVAL_S`). All timing uses the context's `currentTime`, so it pauses while the context is suspended. The gallery has no positional beds.
- Voices: at most 12 SFX voices at once, beds included (`MAX_SFX_VOICES`). A voice past the cap is dropped, never stolen, and counted in `voices.dropped`. A voice frees its slot on `ended`.
- Rustle: in XR only, in a painting's world only (the gallery's strokes do not react), and never at calm 0. A tracked hand (reactive tracker slots 1 and 2, read from its uniforms) fires once when its speed passes 0.6 m/s (`RUSTLE_SPEED`) within `REACTIVE_RADIUS` (0.6 m) of the ground, where the world's `blocked` is true up to 12 m above the ground (`RUSTLE_WALL_TOP`, over the houses and the steeple), or within `REACTIVE_RADIUS` of a free-standing stroke mass (`strokeMassesFor`: in Starry Night, a capsule along each cypress mass's base-to-tip axis, of the seed-1 half widest ring, 1.45 m main and 1.35 m lower). It re-arms below 0.3 m/s. The mixer then plays at most one rustle per 0.25 s (`RUSTLE_MIN_INTERVAL_S`) and two at once (`RUSTLE_MAX_VOICES`). A refused one counts in `rustle.limited`.
- Listener: after each frame's render, from `renderer.xr.getCamera()` while presenting and the desktop camera otherwise, through `positionX`, `forwardX`, `upX` and the rest, or `setPosition` and `setOrientation` where the engine lacks those params. It costs nothing before the unlock.
- Suspension: the context suspends while the page is hidden outside XR, or while the XR session's `visibilityState` is `hidden` (for example the headset taken off), and resumes after. The page's own visibility is ignored while presenting. Each request waits for the previous suspend or resume (each wait capped at 500 ms, `STATE_CHANGE_WAIT_MS`, because a resume without activation can stay pending) and then re-checks what is wanted, so a hide and show quicker than one suspend still ends running.
- Dispose, on `pagehide` unless the page goes into the back-forward cache: stops every voice, disconnects every node (sources, voice gains, panners, buses, master), drops every buffer and closes the context.
- With `?diag` outside `?bench`, `__goghDiag().audio` is `{ state, unlocked, muted, manifest, buses: { music, sfx }, voices: { music, sfx, max, dropped }, score: { target, playing, crossfading }, cues, buffers, rustle: { played, limited }, bell: { rung, nextS } }`. Before the unlock, `state` is `'none'`, `manifest` is `'pending'` and `score.target` is the score the bound world asks for. `cues` maps each cue id to `pending`, `loaded`, `missing` or `error`. A score reads `loaded` once its bytes are fetched, and decodes on demand. `buffers` counts decoded buffers, and `nextS` is the next bell's `currentTime`, or null.
